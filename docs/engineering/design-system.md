# Design System

## Direction

This is an operational academy management app. It should feel quiet, dense, and reliable rather than decorative or marketing-like.

## shadcn Baseline

- Use shadcn/ui components generated by CLI.
- Keep `components.json` as the source for shadcn paths, aliases, style, RSC, and icon library.
- Use semantic CSS variables for theme tokens.
- Use lucide icons for icon buttons and menu actions.

## Layout

- Primary shell: persistent sidebar with five main menu groups.
- Main content: compact headers, toolbar filters, table or calendar body.
- Use tabs for sub-areas such as student/teacher/vendor and income tabs.
- Use dialogs for create/edit flows.
- Use drawers or side panels only when a workflow benefits from staying in context.

## Tokens

- Use semantic tokens: `background`, `foreground`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `ring`.
- Add domain status tokens only after component needs are clear:
  - present
  - absent
  - makeup
  - pass
  - unpaid
  - paid
  - expiring
- Avoid single-hue palettes. Use restrained neutral surfaces plus limited status colors.

## Interaction Rules

- Icon buttons need accessible names and tooltips when meaning is not obvious.
- Text must fit inside buttons and table cells at mobile and desktop widths.
- Prefer role/label-visible controls over hidden affordances.
- Tables need stable row heights, pagination, search, and clear empty states.
- Calendar interactions must be keyboard and pointer accessible where practical.

## Visual Verification

Every major UI flow should be checked at desktop and mobile widths. Verify:

- no overlap
- stable button sizes
- readable Korean text
- visible focus states
- no nested cards
- no decorative gradients or orbs

# 개발 착수 순서

이 문서는 PDF를 읽은 뒤 실제 개발을 어떤 순서로 진행할지 정리한 기준이다.

## 0단계: 기반 세팅

목표: 개발 가능한 Next.js + shadcn + Supabase + 테스트 환경을 만든다.

상태: 완료. 상세 증거는 `docs/harness/evidence/2026-08-20-foundation.md`에 기록한다.

- Next.js App Router + TypeScript 프로젝트 scaffold
- pnpm lockfile 생성
- shadcn/ui 초기화
- Tailwind semantic token 기본값 정리
- Vitest, React Testing Library, Playwright 설치
- Supabase SSR 클라이언트 구조 준비
- 기본 명령 등록: `lint`, `typecheck`, `test`, `test:components`, `test:e2e`, `build`

완료 조건:

- 빈 앱이 빌드된다.
- 기본 테스트가 실패/성공 흐름을 검증할 수 있다.
- shadcn 버튼 또는 기본 shell smoke test가 통과한다.

## 1단계: 도메인 모델과 순수 로직

목표: UI보다 먼저 핵심 규칙을 테스트 가능한 로직으로 만든다.

- 악기, 레슨형태, 출석상태, 회차권, 수강료, 할인, 급여 타입
- 회차권 차감 규칙
- 결석/보강/패스 상태 전환
- 비율제 급여와 3.3% 원천징수 계산
- 교재 출고/결제 완료가 재고와 ledger에 주는 영향

완료 조건:

- 핵심 도메인 규칙 unit test 통과
- UI 없이도 계산/상태 전환이 검증된다.

## 2단계: 인증과 권한 골격

목표: 원장, 데스크, 선생님 역할을 코드 구조와 테스트 기준으로 만든다.

- Supabase Auth SSR helper
- role/permission helper
- 보호 route 기준
- 권한별 메뉴 노출 테스트

완료 조건:

- 익명 사용자는 앱 데이터 화면 접근 불가
- 원장/데스크/선생님별 메뉴 노출이 테스트된다.

## 3단계: 원생/선생님 관리

목표: 다른 기능의 데이터 원천을 먼저 만든다.

- 원생 등록/수정/검색
- 악기별 상세 설정
- 선생님 등록/수정
- 가격표/할인 reference data
- 휴원/퇴원 상태 전환

완료 조건:

- 원생 등록 시 악기별 수강 설정이 저장된다.
- 학생 목록 검색/정렬/페이지 크기 기준이 테스트된다.

## 4단계: 개인레슨표와 회차권

목표: 가장 중요한 회차권 차감 규칙을 사용자 흐름으로 구현한다.

- 회차권 신규 등록/추가
- 개인레슨 등록
- 선생님-시간 중복 방지
- 출석 확인 시 회차권 1회 차감
- 결석 시 회차 미차감
- 학생 시간표 텍스트 복사

완료 조건:

- PDF 핵심 규칙이 unit/component/E2E로 검증된다.

## 5단계: 학원 피아노 레슨표

목표: 반복 일정, 출결, 보강/패스 흐름을 만든다.

- 원생 요일 설정 기반 반복 일정
- 날짜별 출석 확인
- 결석 인원 목록
- 보강/패스 처리
- 월별 메모

완료 조건:

- 보강 확정 시 `[보강 수업]` 일정과 메모가 생성된다.
- 결석은 회차권을 차감하지 않는다.

## 6단계: 교재 관리

목표: 교재 입고부터 결제 완료까지 흐름을 만든다.

- 교재 등록/재고
- 구매 목록
- 출고
- 결제 완료
- 결제 완료 후 ledger 반영

완료 조건:

- 출고 시 재고가 감소한다.
- 결제 완료 시 수입 내역이 생성된다.

## 7단계: 수입/급여 관리

목표: 운영 숫자를 한 화면에서 확인한다.

- 고정 수입과 미납
- 입출입 내역
- 교재 내역
- 선생님 월급
- 전체 수입 그래프

완료 조건:

- ledger가 전체 수입의 source of truth로 동작한다.
- 급여 지급 시 지출 내역이 생성된다.

## 우선 시작점

다음 개발 작업은 **1단계 도메인 모델과 순수 로직**이다. 먼저 회차권 차감 규칙, 출석/결석 상태 전환, 급여 계산 중 제품 정책 확인이 덜 필요한 범위부터 테스트를 작성한다.

# 기존 이메일 로그인 유지 (2026-10-27)

## 발견·계획

- 일반 로그인 화면에는 카카오 버튼만 있었고 이메일·비밀번호 로그인은 원장 연결용 경로에만 남아 있었다. 사용자 요청에 따라 일반 로그인 화면에 기존 이메일 로그인을 복원한다.
- 신규 계정의 가입은 카카오로 진행한다. Supabase의 전체 신규 가입 허용은 유지하고 Email provider의 이메일 신규 가입만 끄는 운영 설정을 사용한다.
- 기존 원장의 카카오 연결은 `auth.users.id`를 유지한 채 identity를 추가한다. 학원·멤버십 등 기존 데이터는 그 ID를 계속 참조하며, 카카오 사용자 데이터로 옮기거나 복사하지 않는다. 실제 연결은 운영 환경에서 확인해야 한다.

## Red → Green → Refactor

- 로그인 화면에 이메일 필드가 나타나고 로그인 성공 후 학원을 다시 조회하는 테스트를 먼저 추가했다. 처음에는 필드가 없어 2건이 실패했다.
- 로컬 개발 환경의 `NEXT_PUBLIC_PREFILL_LOGIN_EMAIL`·`NEXT_PUBLIC_PREFILL_LOGIN_PASSWORD` 자동 입력과 운영 화면의 빈 입력을 테스트했다. 자동 입력 테스트가 처음에 실패했다.
- `EmailSignInForm`을 분리해 `signInWithPassword`와 성공 후 학원 query 무효화를 연결했다. 잘못된 인증정보는 한국어 안내로 변환했다. 자동 입력은 개발 환경에서만 적용했다.
- 폼의 입력·상태·오류 책임을 한 컴포넌트에 두고 렌더 구조를 다시 정리했다.

- UI 증거는 React Testing Library의 로그인 폼·자동 입력·학원 조회 테스트다. 실제 이메일 로그인·카카오 연결·Supabase 콘솔 설정은 배포 전 운영 검증이 필요하다. 원격 DB 변경은 수행하지 않았다.

## Consolidate

- **가독성:** 카카오 로그인 버튼과 이메일 폼을 나누고 입력 필드의 접근 가능한 이름을 유지했다.
- **예측 가능성:** 이메일 로그인 성공 때만 학원 정보를 다시 조회하고 실패 시 세션 화면에 머무른다. 자동 입력은 개발 환경에 한정된다.
- **응집도:** 로그인 폼의 입력·제출·오류는 `src/features/auth`에 모았다.
- **결합도:** 기존 원장 연결 경로와 DB 권한 경계는 건드리지 않았다. 일반 로그인과 기존 학원 조회는 query 무효화로 연결했다.
- **simplify 결과:** 기존 원장 연결 폼의 owner 검사와 일반 이메일 로그인은 목적이 달라 공통 컴포넌트로 합치지 않았다. 추가 인증 경로와 DB migration은 만들지 않았다.

## 남은 위험

- Supabase 콘솔에서 Email provider가 켜져 있고 이메일 신규 가입만 꺼졌는지 확인해야 한다. 카카오 가입을 위해 전체 신규 가입 허용은 켜둔다.
- 기존 원장과 카카오 계정의 이메일이 달라 자동 연결은 발생하지 않는다. 기존 계정으로 로그인한 뒤 수동 연결하고 동일한 사용자 ID·학원·멤버십 및 로그아웃 뒤 카카오 재로그인을 확인해야 한다.
- 기존 원장 프로필의 휴대폰 입력, migration 순서, 실제 RLS 실행 검증은 가입 전체 작업의 선행 보완 사항으로 남아 있다.

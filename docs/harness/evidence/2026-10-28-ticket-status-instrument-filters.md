# 회차권 상태 탭과 레슨시간표 악기 필터 검증

## 발견과 계획

- 회차권 조회는 삭제·환불 후 원본이 사라져 사용취소를 조회할 수 없었다. 기존 감사 이력은 일부 필드만 남긴다. 새 이력은 기존 삭제 RPC와 같은 트랜잭션에서 저장하고, 과거에 확인할 수 없는 값은 비워 둔다.
- 레슨시간표에는 악기 필터가 없었고 학원 달력과 숨긴 일정에는 악기 식별자가 전달되지 않았다. 달력·표·출석창의 표시 대상을 같이 제한한다.
- 가독성: 상태 분류는 도메인에 두고, 삭제 이력 표와 재사용 가능한 상태 탭을 분리했다.
- 예측 가능성: 만료일 당일은 유효하고 잔여 2회 이하를 부족으로 취급한다. 삭제 이력 저장 실패 시 삭제도 롤백된다.
- 응집도: 악기 필터와 날짜별 대상은 시간표 workspace에서 계산하고, 색상 선택은 설정 폼에서 담당한다.
- 결합도: 공통 상태 탭은 라벨·값·점 색상만 받으며 선택 상태는 기존 Tabs가 관리한다. 이력은 회차권 잔액과 별도 테이블에 둔다.
- simplify 목표: 기존 Tabs와 목록 부품을 조합하고 환불 계산을 복제하지 않는다.

## Red → Green → Refactor

- 악기별 선택·중복 색상, 달력과 출석창 필터, 회차권 상태 그룹과 만료 경계, 이력 migration, 재사용 상태 탭을 먼저 실패시켰다. 기존 테스트는 새로운 상태 탭과 기본 사용중 정책에 맞췄다.
- 시간표 선택 항목과 출석 저장 대상이 동일한 필터를 사용한다. 색상 메뉴는 서버 값이 갱신되어야 새 값을 표시해 오류 시 이전 색을 유지한다.
- 재사용 상태 탭은 기존 shadcn Tabs를 사용하고 상태별 문구와 색상은 호출부에서 제공한다.
- 개인레슨 악기 필터는 레슨원생 검색 버튼 바로 왼쪽에 배치하고 학원레슨도 보기 전환 도구 영역에 둔다.

## 검증

- `pnpm test:run`: 최종 216개 파일, 2,219개 테스트 통과. 위치 조정 후 관련 화면·공통 탭 테스트 96개도 통과했다.
- `pnpm lint`, `pnpm typecheck`, `git diff --check`: 위치 조정 후 통과.
- 격리 PGlite: 과거 감사 이력의 불완전한 값, 새 환불 이력, 이력 삽입 실패 시 삭제 롤백, 허용·거부 RLS를 확인했다. 기존 환불 함수를 대역으로 사용한 검증이므로 실제 원격 데이터의 모든 환불 경로를 대체하지 않는다.
- 모바일과 데스크톱 Playwright: 최종 9개 시나리오가 통과했다. 320px 악기 필터와 출석창, 상태 탭, 색상 선택 메뉴 및 기존 시간표 화면을 확인했다. 데모 색상 저장은 기존 빌드에서 실패를 재현한 뒤 설정 저장과 시간표 반영을 검증했다.

## Consolidate와 남은 위험

- 가독성: 이력 표와 공통 상태 탭을 별도 컴포넌트로 분리했다.
- 예측 가능성: 검색과 필터가 바뀌면 첫 페이지로 이동하고, 취소 이력은 회차권 원본에 영향을 주지 않는다.
- 응집도: 상태 판정과 화면 선택, 감사 스냅샷을 각 경계에 모았다.
- 결합도: 기존 환불 함수의 권한·계산을 재사용하고 이력 저장을 트랜잭션에 추가한다.
- simplify 결과: 상태 점과 탭 배치만 공통화하고 화면별 상태와 검색은 호출부에 남겼다.
- 원격 migration은 적용하지 않았다. 적용 전에는 실제 사용취소 이력 조회와 이력 보존이 활성화되지 않는다. 과거 삭제 이력은 남아 있는 감사 정보만 표시한다.
- `pnpm typecheck`가 기존 변경 상태의 자동 생성 `next-env.d.ts`를 다시 썼다. 개발 경로를 참조하도록 Next.js 생성기로 재생성했으나, 실행 전 파일 내용을 저장하지 않아 기존 변경과 바이트 단위 일치 여부는 확인하지 못했다.

## 커밋 전 독립 검토와 보완

- 기능·DB 경계, UI·반응형, simplify 역할의 에이전트가 각각 변경을 검토했다. 필터 밖 날짜 메모의 원생·선생님 후보 누락과 미설정 악기 색상의 화면별 차이를 실패 테스트로 재현한 뒤 수정했다. 기본 색은 악기 ID로 정하므로 기존에 별도 저장하지 않은 악기의 기본 색이 달라질 수 있다.
- 재사용 상태 탭은 항목이 많거나 이름이 길 때 가로 스크롤하도록 정리했다. 날짜 메모 후보는 필터 전 전체 일정에서, 출석 대상은 필터 결과에서 계산한다.
- 이관 전후 삭제 이력 누락을 막기 위해 이관 중 회차권 테이블을 잠그고 기존 RPC의 감사 이벤트도 포착한다. 인증된 사용자가 해당 감사 이벤트를 직접 만들어 이력을 위조하지 못하도록 제한 정책을 추가했다. 회차권 삭제·수정·서비스 회수는 같은 범위 잠금을 먼저 획득한다.
- 격리 PGlite에서 정상 이력, 기존 감사 이벤트 포착, 저장 실패 롤백, authenticated 위조 입력 거부와 RLS를 확인했다. 실제 PostgreSQL의 두 동시 세션은 실행 환경에 없어 검증하지 못했다. 이관 중 이미 시작된 기존 RPC와 새 RPC가 잠시 경쟁하면 기존 잠금 순서로 인해 교착 감지 후 한 요청이 롤백될 가능성이 남는다. 이관 당시 이전 RPC가 남기는 감사 이벤트의 정보는 일부만 복원될 수 있다.
- Claude Code `/simplify`는 로그인되지 않아 실행하지 못했다. 독립 에이전트 검토와 책임자 확인으로 대체했고, `.agents/skills/simplify/SKILL.md`를 추가해 재사용성·품질·효율성 검토와 수정·검증을 다음 커밋 요청에도 적용하도록 했다. 스킬 검증기는 기존 `js-yaml` 기반 YAML 파서로 실행해 통과했다.
- 가독성·응집도: 색상 기본값 계산을 공통 함수로 모으고 메모 대상과 출석 대상을 분리했다. 예측 가능성: 상태 전환 중 이전 목록을 표시하지 않는다. 결합도: 이력 조회의 단일 화면 전용 코드는 feature에 유지했다. simplify 결과: 재사용 탭의 범위를 유지하고 불필요한 별도 목록 추상화는 추가하지 않았다.
- 재검증: `pnpm test:run` 216개 파일·2,223개 테스트 통과, 영향받은 Vitest 26개 통과, `pnpm lint`, `pnpm typecheck`, 데모 빌드와 Playwright 9개 통과. 최종 SQL 변경 후 계약 테스트와 격리 DB 검증을 다시 실행했다.

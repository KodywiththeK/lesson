# 레슨 월별 메모지 다이얼로그화와 선택 날짜 패널 제거

## 요약

- 요청(2026-10-21): (1) 월별 메모지를 다이얼로그로 열고, 여는 버튼을 뷰와 상관없이 보기 전환 탭과 같은 줄에 두며, 메모지답게 꾸민다. (2) 캘린더가 오른쪽 패널 때문에 좁아 보이므로 패널을 없애고, 변경 이력은 출석 확인 모달로 옮기며, 출석 확인 모달은 최소 높이를 60vh로 키운다.
- 이전 디자인 정비(1~4단계)와 달리 화면 구조와 동작이 바뀌는 작업이다. 데이터·권한·저장 로직은 바꾸지 않았다.
- 앞선 [4단계-5 레슨 영역](./2026-10-21-ui-redesign-stage4-lessons.md)과 같은 날의 후속 작업이다.

## 변경 내용

- 월별 메모지 (`src/features/lessons/lesson-monthly-note.tsx`)
  - `LessonMonthlyNotePostit`을 `LessonMonthlyNoteDialog`로 바꿨다. "메모지" 버튼을 누르면 `{월}월 {학원|개인}레슨 메모지` 다이얼로그가 열리고, 미확인 메모가 있으면 버튼에 "미확인" 표시가 붙는다. 접기·펼치기는 없앴다.
  - 초안·충돌 처리는 그대로이고, 다이얼로그를 닫아도 컴포넌트 상태에 남아 다시 열면 이어진다.
  - 메모지 모양: 노란색(`warning-soft` 토큰) 종이, 위쪽 테이프 장식, 줄이 그어진 입력칸(줄 높이 1.75rem과 같은 글줄 간격), 갈색 계열 글자. 저장·확인·닫기는 한 줄에 둔다.
- 워크스페이스 (`lesson-management-workspace.tsx`)
  - 메모지 버튼을 `LessonViewTabs`의 `actions`로 넘겨 학원·개인 모두 캘린더뷰·테이블뷰에서 보기 전환 탭과 같은 줄 오른쪽에 둔다. 개인레슨은 "레슨원생 검색" 버튼 옆이다. 관리 권한이 없으면(선생님) 버튼을 두지 않는다.
  - `LessonCalendarSidePanel`과 그 테스트를 삭제했다. 달력이 본문 폭을 다 쓴다. 테이블뷰 위에 펼쳐 두던 메모지도 없앴다.
- 출석 확인 모달 (`academy-day-attendance-dialog.tsx`, `private-day-attendance-dialog.tsx`)
  - `history` 속성을 받아, 관리 권한이 있고 이력이 주어지면 "변경 이력" 탭을 보여 준다. 워크스페이스는 서비스에 연결된 경우에만 `LessonAuditHistory`를 넘긴다. 탭을 열 때 이력을 불러오므로 모달을 열 때마다 조회하지 않는다.
  - 최소 높이를 `min-h-[60vh]`로 두고 본문 행이 남는 높이를 차지하게 했다(`grid-rows-[auto_1fr_auto]`). 수업이 적어도 카드는 위쪽에 붙는다(`content-start`).
- 문서: `docs/product/functional-spec.md`의 메모지·선택 날짜 서술과 `docs/harness/decision-log.md`에 2026-10-21 결정을 기록했다(2026-10-20 "달력 옆 고정 패널" 결정을 대체).

## 연결된 요구사항

- `docs/product/functional-spec.md`의 월별 메모(메모지), 달력, 출석확인 항목. 이력 조회 권한(관리 권한)과 선생님 화면에서 메모지가 보이지 않는 규칙은 그대로다.

## 먼저 작성한 테스트와 Red 확인

- `lesson-monthly-note.test.tsx`를 새 동작(버튼으로 열기, 다이얼로그 이름, 닫았다 열어도 초안 유지, 미확인은 열기 전에도 버튼에 표시)으로 다시 쓰고, 컴포넌트가 없는 상태에서 11개가 모두 실패하는 것을 확인했다.
- `academy-day-attendance-dialog.test.tsx`(신규)와 `private-day-attendance-dialog.test.tsx`에 변경 이력 탭 테스트를 먼저 추가했고, 구현 전에 이력 탭 확인 2개가 실패하는 것을 확인했다. 탭이 없어야 하는 경우(이력 없음, 권한 없음)는 처음부터 통과했다.
- `lesson-management-workspace.monthly-note.test.tsx`는 새 흐름(평소엔 닫힘, 보기 전환 줄의 버튼, 캘린더·테이블뷰 모두 존재, 권한 없으면 없음, 실서비스 경로의 미확인·저장·불러오기 실패)으로 고쳤다. 같은 줄 배치 테스트는 버튼과 탭 목록이 같은 줄 컨테이너를 공유하는지 확인한다.
- `tests/e2e/home.spec.ts`: 기존 "달력과 선택 날짜 패널" 검사를 "패널 없음, 1280px에서 달력 폭 900px 이상, 메모지 버튼이 보기 전환 탭과 같은 줄, 가로 넘침 없음"으로 바꾸고, 학원·개인 두 화면에서 메모지 다이얼로그가 열리고 출석 확인 모달의 계산된 `min-height`가 viewport 높이의 60%(900px에서 540px)인지 확인하는 테스트를 추가했다. 처음에는 열림 애니메이션 중 `boundingBox` 높이로 재서 실패했고, 애니메이션에 흔들리지 않는 `toHaveCSS`로 바꿨다.
- 기존 테스트 중 상시 노출되던 메모지를 전제로 한 8개(`monthly-note` 6개, 날짜 모달 탭 1개, 결석 사유서 자동 기록 1개)가 의도대로 실패했고 새 동작 기준으로 고쳤다. 결석 사유서 자동 기록 테스트는 결석인원 다이얼로그를 닫고 메모지를 여는 순서로 바꿨다.

## 브라우저 증거

- 데모 production build를 `next start -p 3107`로 띄워 Playwright로 촬영해 직접 확인했다: 1280px 학원레슨 캘린더(패널 없음, 달력이 본문 폭 전체), 메모지 다이얼로그(1280px 학원·개인, 390px 개인), 390px 개인레슨 캘린더(버튼 두 개가 보기 전환 아래 줄 오른쪽), 1280px 개인레슨 출석 확인 모달(60vh 높이, 카드가 위쪽에 붙음), 1280px 학원레슨 출석 확인 모달.
- 촬영 중 발견해 고친 문제: 출석 확인 모달이 최소 높이를 채우려고 수업 카드를 세로로 늘려 가운데에 띄웠다(`content-start`로 해결). 메모지의 저장·닫기가 서로 다른 줄에 있었다(한 줄로 합침).
- 변경 이력 탭은 서비스 연결(Supabase 클라이언트)이 있어야 나타나서 데모 화면에서는 볼 수 없다. 탭 표시·권한 분기는 단위 테스트로만 검증했고 실제 이력 조회 화면은 확인하지 못했다. 메모지 로딩·오류 상태와 390px 테이블뷰는 촬영하지 않았다.

## Supabase 증거

해당 없음. DB, migration, RLS를 건드리지 않았다. 월별 메모 API(`fetchLessonMonthlyNote`, `saveLessonMonthlyNote`, `markLessonMonthlyNoteRead`) 호출 인자는 기존 실서비스 경로 테스트로 그대로 검증된다.

## Quality Consolidation

- 가독성: 워크스페이스에서 "달력 + 사이드 패널" 이중 그리드와 `monthlyNotePostit` 중복 렌더(캘린더·테이블 각각)가 사라지고, 메모지 버튼 하나가 `LessonViewTabs`에 들어간다.
- 예측 가능성: 메모지는 두 레슨 종류·두 보기에서 항상 같은 자리의 같은 버튼이다. 변경 이력은 두 출석 확인 모달에서 같은 "변경 이력" 탭 이름과 조건(관리 권한 + 서비스 연결)으로 나타난다.
- 응집도: 메모지의 모양·초안·저장 UI가 `lesson-monthly-note.tsx` 한 곳에 있다. 이력 탭 조건(`canManage && history !== undefined`)은 각 모달에 있으나 같은 한 줄이다.
- 결합도: 모달은 `history`를 `ReactNode`로 받아 `LessonAuditHistory`나 Supabase를 모른다. 이력 요소는 워크스페이스가 만든다.
- simplify 결과: 사용하지 않게 된 `LessonCalendarSidePanel`과 접기 상태(`isCollapsed`), 패널용 `xl:grid-cols` 래퍼를 제거했다. `PostitBody`의 `onClose`는 편집기에서만 쓰여 로딩·오류 상태에는 닫기 버튼 대신 다이얼로그의 X 버튼을 쓴다.
- Warning(남김): 메모지 로딩 오류 메시지가 다이얼로그를 열어야 보인다. 이전에는 메모지가 항상 보여서 오류도 바로 보였다. 오류가 있어도 버튼은 평소와 같다.
- Warning(남김): 이전의 "선택한 날짜 수업 목록 + 열기" 요약이 사라져, 날짜별 수업은 칸을 눌러 모달을 열어야 읽는다. 작은 모바일에서 날짜 칸이 건수만 보이므로 상세를 보려면 한 번 더 눌러야 한다. 사용자 결정이지만 실사용 후 불편하면 재검토한다.
- Warning(남김): `lesson-management-workspace.private-absence.test.tsx`의 `.justify-between`, `.ml-auto` 조상 탐색은 이번 변경으로 깨지지 않았지만 여전히 클래스에 묶여 있다.

### migration 재점검과 적용
- **읽기 전용 스키마 확인**(원격 카탈로그, 데이터 행 미조회): 대상 함수의 시그니처·반환 타입·`security` 속성, `fixed_income_snapshots_status_check`(`unpaid, paid`뿐), `salary_settlements` unique, `book_releases` 컬럼·trigger를 확인해 migration의 가정과 같음을 확인했다.
- **독립 SQL 리뷰**(읽기 전용 에이전트): 판정 "수정 후 적용". 지적과 처리 — F-01 Critical(미납 해제가 UI에서 항상 실패: 화면이 입금 취소 RPC로 연결) → 전용 RPC `clear_fixed_income_snapshot_overdue`와 화면 연결로 수정, F-02 비율제 등원 기록 없음 거부, F-04 월급제 수업 id 저장 제거, F-05 anon 직접 실행 권한 회수, F-07 원장 연결 id가 비어 있어도 ref로 원장 삭제, F-08 이미 미납 재처리 거부·월 하한. F-06(backfill 결정성)과 F-03(전체 조회, C-1로 해소)은 별도 처리.
- **적용**: `pnpm supabase db push --dry-run`(대상이 이 파일 하나뿐) → `db push --yes`, 원격 history가 로컬 파일명과 일치. 적용 후 카탈로그 검증: status check `unpaid, paid, overdue`, 함수 8종 anon 실행 불가·authenticated 실행 가능, `book_releases.paid_ledger_entry_id`와 FK, `mark_salary_settlement_paid`의 lock·`Asia/Seoul`·비율제 가드, 최종 수정 마커(미납 중복 거부·ref fallback·월 하한·월급제 id)가 원격 함수 정의에 모두 존재(로컬 파일과 같은 버전). 이어서 `notify pgrst, 'reload schema'`. PostgREST `max_rows`는 1000(페이지 크기와 일치).
- **한계**: 운영 데이터 행은 읽지 않았다. 동시 지급 락, 서버 재계산 일치, 교재 backfill 결과 같은 **실제 DB 동작은 계약 테스트와 문법 검사까지만** 검증했다.

### Critical 처리
| 항목 | 처리 |
| --- | --- |
| C-1 조회 1000행 절단 | `fetchAllPages`(1000건씩 끝까지, 50페이지 초과 시 한국어 오류)와 월/연도 서버 필터 + 안정 정렬(`order`, 유일 키 `id`). 원장·급여용 수업(한국 시간 월 범위)·정산·교재(입금일 월)·연간 수강료(`status=paid`)·그 외 전체 조회까지 적용. 전체 수입은 연도 원장을 자체 쿼리로 읽고, 회차권 원장은 월과 무관하게 함께 읽는다(다른 달로 옮긴 원장을 누락으로 오해하지 않게) |
| C-2 급여 금액 검증 | 서버: 등원 수업 id 집합이 그 선생님·그 달의 실제 등원 수업 전체와 같은지, 월급제·시급제 재계산, 세금(3.3% 내림), 미래 월·NULL·0원 거부, 비율제는 등원 기록 필요. 화면: 지급 확정 직전 그 달 데이터를 다시 불러와 금액·수업이 달라졌으면 지급하지 않음(재조회가 실패하면 직전 성공값을 최신으로 착각하지 않고 오류) |

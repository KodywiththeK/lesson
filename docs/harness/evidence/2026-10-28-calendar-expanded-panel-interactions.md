# 레슨 달력 확대 패널 클릭·드래그·중앙 배치 검증

## 발견과 계획

- 연결 요구사항: 학원·개인레슨 달력에서 4건 이상인 날짜의 확대 패널을 클릭하면 해당 날짜 출석 확인을 열고, 패널 속 네 번째 이후 일정을 다른 날짜로 드래그하며, 패널은 날짜 칸 중앙에서 확장한다. 인수 기준은 `docs/product/acceptance-scenarios.md`에 갱신했다.
- 기존 패널은 클릭 전파를 막고, 마우스가 원래 칸을 벗어나면 드래그 중에도 패널을 제거했다. 좌상단·우하단 기준 위치 지정으로 중앙 확장이 아니었다.
- 가독성: 날짜 선택은 기존 칸의 `onClick`을 재사용하고, 패널 크기·위치는 하나의 계산 함수에 둔다.
- 예측 가능성: 드래그가 시작되면 원본 DOM을 유지하고 종료 시 정리한다. 화면 가장자리에서만 중앙 위치를 보정한다.
- 응집도: 호버·드래그 상태와 패널 위치 계산은 공통 `LessonMonthCalendar` 안에 둔다.
- 결합도: 학원·개인레슨 화면의 기존 `onSelectDate`·`onMoveEvent` 계약을 그대로 사용한다.
- simplify 목표: 날짜별 방향 분기와 클릭 차단을 없애고, 패널 표시·드래그 정리를 명명된 상태로 모은다.

## Red → Green → Refactor

- 학원·개인레슨 각각 확대 패널의 일정·빈 곳 클릭, 네 번째 일정 드래그 후 다른 날짜 드롭, 중앙 좌표와 화면 경계 보정 테스트를 먼저 추가했다. 최초 실행 15개 중 새 테스트 5개가 클릭 0회, 드래그 중 패널 제거, 좌상단 배치로 의도대로 실패했다.
- 클릭 차단을 제거하고 패널을 날짜 칸의 자식으로 유지했다. 드래그 시작은 즉시 참조값에 기록해 마우스 이탈 시 원본 요소가 제거되지 않도록 했다. 패널 크기를 날짜 칸 기준 약 2배로 계산하고 중앙에 놓되 화면에서 16px 여백을 유지한다.
- 실제 Chromium 검증에서 드래그 중 패널 전체에 `pointer-events: none`을 적용하면 HTML 드래그가 끝나지 않는 문제를 찾았다. 패널을 DOM에 둔 채 뒤로 보내고 투명하게 처리해 드롭 날짜가 입력을 받도록 바꾼 뒤 실제 포인터 드래그가 통과했다. 브라우저 검증용 임시 화면·테스트는 검증 후 제거했다.

## Consolidate와 남은 위험

- 가독성: 클릭은 기존 날짜 칸의 이벤트 버블링으로 연결해 별도 모달 호출을 만들지 않았다.
- 예측 가능성: 드래그 중 패널을 DOM에서 제거하지 않고 화면 뒤로 보내며, 드롭·드래그 종료 때 상태를 비운다.
- 응집도: 호버 지연, 위치 계산, 드래그 수명 주기가 한 컴포넌트에 모여 두 레슨표가 같은 동작을 갖는다.
- 결합도: 출석 확인 창과 일정 이동의 상위 콜백을 수정하지 않아 다른 화면의 저장 정책에 영향을 주지 않는다.
- simplify 결과: 날짜 위치 인덱스로 좌우·상하를 고르던 분기와 패널 클릭 차단을 제거했다. 즉시 드래그 판정용 ref와 시각 상태는 역할이 달라 함께 유지했다. 변경 파일을 다시 읽고 Critical·Warning 품질 문제는 발견하지 못했다. 커밋 전 Claude Code `/simplify` CLI는 로그인되지 않아 실행되지 않았으므로 위 수동 네 기준 검토로 마무리했다.
- 실제 운영 계정에서 일정 저장까지는 수행하지 않았다. 이번 변경은 달력 상호작용에 한정되며 DB schema·RLS·migration 변경은 없다. 후속 사용자 요청에 따라 이번 변경만 커밋·push한다.

# 브랜드 로고와 검색 노출 설정

## 요약

- 목표: 제공된 마디마디 로고·공유 썸네일·대표 문구를 앱과 검색 메타데이터에 반영한다.
- 완료한 변경: 데스크톱 사이드바·모바일 메뉴·로그인 전 화면에 로고를 배치하고, 공식 도메인의 canonical·Open Graph·Twitter 카드·사이트맵을 설정했다. 제공된 파비콘·Apple 아이콘·Android 아이콘을 메타데이터와 manifest에 연결했다. 운영 경로에는 `X-Robots-Tag: noindex, nofollow`를 적용했다.
- 커버한 요구사항: `docs/product/acceptance-scenarios.md`의 브랜드와 검색 노출 시나리오 3건. 추적 위치는 `docs/product/traceability-matrix.md`에 기록했다.

## 먼저 작성한 테스트

- 테스트 파일: `src/app/layout.test.tsx`, `src/app/manifest.test.tsx`, `src/app/seo-routes.test.tsx`, `src/app/app-shell.test.tsx`, `src/features/auth/academy-session-gate.test.tsx`, `tests/e2e/home.spec.ts`.
- 시나리오: 브랜드 메타데이터, 사이트맵과 운영 경로 검색 제외, 사이드바·모바일 메뉴·로그인 로고, 실제 썸네일과 아이콘 응답을 확인한다.
- 초기 실패: 기존 메타데이터에 브랜드·공유 이미지가 없고, `robots.ts`와 로고 요소가 없어 테스트가 실패했다. 첫 E2E에서 canonical의 끝 슬래시 표기 차이를 발견해 기대값을 맞췄다. 이어 운영 경로 헤더가 없음을 확인해 실제 적용되는 `next.config.ts` 정적 헤더로 옮겼다. 이후 파비콘 테스트는 `metadata.icons` 누락과 `manifest.ts` 부재로 실패했고 연결 후 통과했다.

## 브라우저 증거

- URL: `http://localhost:3001/`(기존 실행 중인 개발 서버), E2E의 데모 빌드.
- 데스크톱 스크린샷: Chrome 화면에서 사이드바 상단 로고가 현재 학원명 위에 있고 이미지가 선명하게 표시되는 것을 확인했다. 스크린샷 파일은 저장하지 않았다.
- 모바일 스크린샷: 320px Chrome 화면에서 메뉴를 열어 로고·학원명·목록의 겹침과 잘림이 없음을 확인했다. 스크린샷 파일은 저장하지 않았다.
- 비고: E2E에서 로고 이미지의 실제 로딩, 공유 썸네일의 `image/webp` 응답, canonical·OG URL, 아이콘 링크·응답, 운영 경로 헤더, 사이트맵을 확인했다.

## Supabase 증거

- Migration: 없음.
- RLS 확인: 데이터 권한 변경 없음. 검색 제외 헤더는 인증·RLS를 대신하지 않는다.
- 역할별 확인: 이번 변경은 역할별 데이터 접근에 영향을 주지 않는다.
- 비고: 운영 DB에 접속하거나 변경하지 않았다.

## 품질 정리

- 코드 단순화: 검색 문구·URL·이미지 경로를 `src/app/seo.ts`로 모았고 로고 렌더링을 `BrandLogo`로 합쳤다. 검색 제외 경로 테스트의 조건식과 들여쓰기를 정리했다. 아이콘은 기존 파일을 메타데이터·manifest에 직접 연결해 별도 이미지 처리 로직을 만들지 않았다.
- 재사용한 추상화: 기존 `next/image`, App Router metadata·robots·sitemap, Next 정적 헤더를 사용했다.
- 테스트 정리: 메타데이터 단위 계약에 메뉴 경로 검색 제외 커버리지와 실제 이미지 응답 E2E를 추가했다.
- 가독성: 브랜드 값과 공개·비공개 경로의 목적을 이름으로 구분했다.
- 예측 가능성: URL을 한 곳에서 관리하고, 운영 경로는 렌더링 상태와 무관하게 응답 헤더에서 제외한다.
- 응집도: 검색 설정은 `seo.ts`·App Router 파일·`next.config.ts`, 로고 표시는 단일 컴포넌트에 둔다.
- 결합도: 사이드바·드로어·로그인 화면은 `BrandLogo`만 사용하고 이미지 파일의 세부 경로를 알지 않는다.
- simplify 결과: 별도 프록시 로직과 중복 로고 마크업을 두지 않았다. 변경 diff를 재검토한 뒤 영향 테스트를 재실행했다.
- 코드 품질 리뷰: Critical 없음. 테스트용 경로 커버리지와 실제 빌드 동작을 교차 확인했다.
- 남긴 Warning/Suggestion: `proxy.ts`가 현재 `src/app` 구조에서 실행되지 않는 기존 배치 문제를 발견했다. 이번 SEO는 `next.config.ts`로 해결했지만 세션 갱신 경로는 별도 점검이 필요하다.
- 남은 부채: 검색 가능한 공개 본문이 로그인 전 화면뿐이라 검색 유입을 위한 소개 콘텐츠는 별도 제품 결정이 필요하다.

## 위험과 확인 질문

- 위험: 새 운영 URL이 메뉴 밖에 추가되면 `privateRouteSources`를 함께 갱신해야 한다. 메뉴 경로는 테스트로 감시하지만 숨겨진 새 경로는 리뷰가 필요하다.
- 후속 질문: 없음. 공개 소개 페이지와 세션 프록시 점검은 별도 작업으로 분리한다.

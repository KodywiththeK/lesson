# 명세 검토 1회차: 메뉴 구조·목록 공통 규칙·개인레슨 회차 차감 (2026-10-15)

## 요약

- 목표: 사용자 명세 조각(좌측 메뉴 5개와 역할별 노출, 목록 10개 제한·10/20/30 선택·이름 검색·가나다 정렬, 개인레슨 회차 차감 원칙)과 구현을 역할별 조사관이 대조하고, 명세에 없어도 당연히 필요한 부분(CRUD 완결성, 기본값, 사용자 문구, 화면 간결성)을 보완한다.
- 방식: `/spec-review`. 읽기 전용 조사관 3명(메뉴·권한 / 목록·CRUD / 회차 차감)이 병렬 조사 → 리드가 핵심 주장을 코드로 재확인 → 사용자 결정 4건 → 1단계(정책 불필요 버그)는 리드가, 2단계(목록 공통 규칙)는 파일 소유권을 나눈 구현 에이전트 6명이 TDD로 구현 → 리드 통합·simplify.
- 확정 결정(사용자): 범위는 1+2단계, 퇴원 원생·퇴사 선생님 삭제는 비활성(보관만), 10개 규칙은 관리 표 전체, 메뉴 이름은 현재 유지·홈에서 가짜 수치만 제거.
- **회차 차감 원칙 자체는 운영 경로 RPC(`mark_private_lesson_attendance`)에서 정확하다**(등록만으로 차감 없음, 출석 시 1회, 결석 무차감, 중복 방지, 실패 시 롤백). 문제는 UI 표시·목록 규칙·하드코딩·문구·일부 CRUD 누락이었다.

## 변경 내용

### 1단계: 정책 불필요 버그
- 개인레슨 출석·결석 상태를 출결 기록에서 읽어 재조회·월 이동 후에도 유지, 같은 상태 버튼 비활성, 안내 문구가 실제 회차권 변화를 말함(`describePrivateAttendanceChange`), 회차 소진 오류를 한국어 안내로 변환.
- `2026-08-21` 하드코딩 제거(수납일은 열 때마다 오늘로 시작, 선생님 등록일·휴원/퇴원 기준일을 서울 날짜로, 회차권 기준일은 데모에서만 고정일).
- 회차권 등록 폼: 등록일·유효 시작일 오늘, 악기 하나면 자동 선택, 등록 성공 시 레슨 쿼리 무효화.
- 홈: 세션 게이트, 가짜 수치·개발 메모 제거 → 역할별 바로가기. 권한 없는 주소는 안내 화면(UX용). 죽은 `내 급여` 링크 제거. 로그인 폼 프리필 제거, 인증 오류와 기타 오류(다시 시도) 분리, 사이드바 영문 라벨 정리.
- 사용자 문구: `toUserMessage` 변환 계층과 화면 30여 곳 적용, 개발자용 안내·`archive` 문구 정리, 제목 없는 토스트 보완.
- 개인레슨 등록: 악기 하나일 때만 자동 선택, 담당(또는 같은 파트) 선생님 기본 선택, 재직 선생님만 가나다순, 회차권 없음 경고, 잔여는 오늘 유효한 회차권만 합산.
- 전체수입: 연간 수입·지출·순수익, 월별 수입·지출·순수익.
- 레슨시간표 복사: 복사 실패 시 성공 토스트를 띄우던 문제 수정.

### 2단계: 목록 공통 규칙·CRUD
- 공통 `ListPagination`·`useListPaging`·`paginateItems`·`buildPageNumbers`, 이름 정렬 `compareKoreanNames`(+동명이인 `getTieBreaker`). 관리 표 11종에 총 건수·번호 이동·10/20/30 선택을 항상 노출.
- 옵션 조회 분리: `fetchTeacherOptions`, `fetchStudentOptions`, `fetchAllLessonTickets`(급여 계산·드롭다운이 10건에서 잘리지 않음).
- 휴원/퇴원·레슨수입·교재내역·선생님 월급에 이름 검색과 빈 상태 문구, 필터 선택지를 전체 기준으로, 선생님의 항상 0건이던 상태 필터 제거.
- 거래처 수정 기능과 미저장 "등록일" 필드 제거. 원생 수정의 "악기 ID" 자유 입력을 읽기 전용으로.
- 삭제: 퇴원 원생·퇴사 선생님 삭제 비활성+안내, 입출금·날짜 메모 삭제는 `AlertDialog` 확인.
- 정리: 미사용 `list-toolbar`와 데모의 죽은 삭제·`createDemo*QueryOptions` 제거, 남아 있던 `localeCompare("ko…")` 이름 정렬 통일.
- 날짜·월 필드: 필수 월 필터는 비워도 값을 올리지 않고 포커스를 잃으면 마지막 값으로 복원(비우면 입출금·레슨수입 조회가 깨지던 문제).

## 먼저 작성한 테스트(Red)와 한계

- 각 항목은 실패하는 테스트를 먼저 쓰고 의도한 이유로 실패하는 것을 확인했다(예: `총 25건`/`2페이지` 버튼 없음, `expected [...'teacher-b','teacher-a'] to deeply equal [...]`, 개인레슨 상태 전부 `scheduled`, 급여 계산 12명 fixture, 삭제 확인 `alertdialog` 없음, 수납일 `2026-08-21`).
- **Red를 확인하지 못했거나 구현과 함께 작성한 것**: 개인레슨 출석 후 버튼 비활성 단언, 회차권 등록 폼 기본값 테스트, `pickDefaultTeacherId`/`describePrivateAttendanceChange` 도메인 테스트(테스트와 구현을 연달아 작성), `academy-demo-provider.people-paging` key 테스트 일부, `passes` 페이지의 실서비스 `today` 분기(테스트 없음, 타입체크와 `rg`로만 확인), 일부 회귀 가드는 처음부터 통과.
- 기존 테스트는 약화하지 않았다. 요구가 바뀐 부분만 갱신했다(`permission denied` 원문 → 한국어 안내, 쿼리 key 형태, 버튼 이름 `전체출석` → `현재 목록 N건 출석`, 전체수입 그래프 이름).

## 품질 정리

- **가독성**: 목록 하단 UI·페이지 상태·페이지 자르기·번호 생략·이름 정렬을 이름 붙은 공유 요소로 모아 화면의 조건문과 자체 페이지 UI(원생 55줄 등)를 걷어냈다. 중첩 삼항 없음.
- **예측 가능성**: `build*/fetch*` 이름과 반환이 맞는다(`fetchXList`는 페이지, `fetchXOptions/fetchAll*`는 전체). 검색·필터·크기 변경은 항상 1페이지로, `onValueChange`는 완성된 값만 전달, 성공 문구는 실제 결과를 말한다.
- **응집도**: 목록 규칙은 `common-list.ts`와 `components/management/`, 사용자 문구는 `lib/errors/`, 정책 상수(회차권 임박 기준 등)는 도메인에 있다.
- **결합도**: 화면은 `useListPaging`/`ListPagination`/`buildListView` 조합만 알고, 옵션 조회는 목록 key와 분리된 key를 쓴다. 에러 변환은 한 함수를 통해서만 한다.
- **simplify 결과**: `paginateItems`로 세 곳의 중복 자르기(`buildListView`, 입출금, 레슨)를 합침, 죽은 데모 함수·삭제 코드·`list-toolbar` 제거, `localeCompare("ko…")` 8곳 통일, 본문 일부 재작성.
- **Critical**: 없음(발견 즉시 수정: 개인레슨 출석 상태 소실, 급여 계산 선생님 10명 컷, 월 비움 시 조회 깨짐, 복사 거짓 성공, 수납일 하드코딩).
- **남긴 Warning/Suggestion**:
  - Warning: 홈 바로가기 카드가 사이드바와 같은 메뉴를 한 번 더 보여준다(중복 정보). 사용자가 홈 유지를 정해 두었으므로 유지하되 후속 정리 후보다.
  - Warning: 레슨 일별 출석 표의 행별 버튼 4개(일정 이동·초기화·출석·결석)와 `현재 목록 N건 출석` + 체크박스 + `선택출석`의 기능 중복은 UX 결정이라 건드리지 않았다(드롭다운으로 이동 제안).
  - Warning: 입출금 내역은 월 선택과 시작·종료일이 같은 범위를 이중으로 조작한다(월을 바꾸면 기간이 리셋, 기간을 다른 달로 옮겨도 월 필드·캘린더는 이전 달). 제안만 남김.
  - Warning: 목록은 전체를 한 번 조회해 브라우저에서 자른다(서버 페이지네이션 아님, max-rows·collation 미확인).

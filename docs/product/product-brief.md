# 제품 브리프

## 제품

이 제품은 음악학원 운영자가 가입해 레슨 일정, 회차권, 원생/선생님 정보, 교재 판매, 수납/미납, 지출, 급여 정산을 관리하는 웹 기반 학원관리 서비스다.

첨부 PDF는 더 클래식 음악학원의 실제 운영 문제와 1차 기능 범위를 담은 요구사항 자료다. 다만 최신 사용자 지시에 따라 제품 방향은 더 클래식 전용 내부 도구가 아니라 여러 음악학원 원장과 선생님이 가입해 사용할 수 있는 멀티테넌트 서비스로 둔다.

## 목표

- 회차권 잔여 횟수 계산 오류를 줄인다.
- 원생, 일정, 수강료, 교재, 수입/지출 정보를 한 흐름에서 관리한다.
- 미납 수강료를 놓치지 않게 한다.
- 월별 급여와 정산 업무 시간을 줄인다.
- 단일 학원 운영에 먼저 쓸 수 있으면서, 처음부터 여러 학원 계정과 권한 분리를 전제로 설계한다.

## 주요 사용자

- **서비스 가입자/학원 원장**: 학원을 생성하고 전체 운영, 권한, 재무, 급여, 민감 정보를 관리한다.
- **데스크 직원**: 원생 등록, 일정, 출석, 교재 판매, 수납 같은 일상 운영을 처리한다.
- **선생님**: 본인에게 배정된 수업과 원생을 확인하고, 허용된 범위에서 출석 확인과 보강 처리를 한다.

## 1차 범위

- 역할 기반 로그인과 학원 멤버십
- 학원별 레슨 시간표: 학원 피아노 레슨표, 개인레슨표
- 학원별 회차권 관리
- 학원별 원생, 선생님, 거래처 관리
- 휴원/퇴원 관리
- 교재 재고와 판매 흐름
- 학원 수입 관리, 수납/미납 현황, 지출, 급여 정산

## 명시적으로 후순위

- 그룹수업 정원/대기자 명단
- 카드 단말기 결제 연동
- 카카오 알림톡 자동 발송
- 학부모용/강사용 별도 모바일 포털
- 여러 학원을 대상으로 한 공개 마케팅/요금제 페이지
- 공지사항/이벤트 공유 기능

## 멀티테넌트 원칙

- 모든 운영 데이터는 `academy_id` 또는 동등한 tenant scope를 가진다.
- RLS는 “로그인 여부”가 아니라 학원 멤버십, 역할, 배정 관계를 기준으로 작성한다.
- 선생님은 소속 학원과 배정된 수업/원생 범위 안에서만 접근한다.
- API cache key는 학원 식별자와 사용자 역할을 포함해 학원 간 캐시 오염을 방지한다.
- 더 클래식 요구사항은 초기 reference tenant의 요구사항으로 취급하고, 제품 전체 구조를 단일 학원에 고정하지 않는다.

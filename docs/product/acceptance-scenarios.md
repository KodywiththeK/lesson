# 인수 시나리오

이 문서는 TDD 시작점으로 사용한다. 시나리오가 구현되면 `docs/product/traceability-matrix.md`에 테스트와 구현 위치를 연결한다.

## 공통 목록 동작

조건: 운영자가 원생·선생님·회차권·교재·입출금 목록을 작은 화면에서 연다
동작: 화면을 1024px 표, 768~1023px 행 중심 배치, 481~767px 카드 2열, 480px 이하 카드 1열로 바꿔 본다
결과: 같은 데이터·상태·작업 버튼이 보이고 페이지 전체 가로 넘침이나 잘린 필터가 없다.

조건: 운영자가 원생, 선생님, 거래처, 교재, 수입 내역 같은 업무 목록을 연다  
동작: 별도 페이지 크기를 선택하지 않는다  
결과: 목록은 기본 10개 단위로 표시된다  
그리고: 10개, 20개, 30개 단위로 전환할 수 있다.

조건: 업무 목록에 한글 이름 데이터가 섞여 있다  
동작: 목록을 기본 정렬로 조회한다  
결과: 이름은 `ko-KR` 기준 가나다 순서와 숫자 인식 순서로 정렬된다.

조건: 운영자가 목록 검색어를 입력한다  
동작: 이름, 악기, 담당 선생님 같은 지정 검색 필드와 대조한다  
결과: 검색어가 포함된 항목만 표시된다.

조건: 운영자가 담당 선생님, 악기, 정기 요일 같은 필터를 선택한다  
동작: 목록을 다시 계산한다  
결과: 선택한 필터 조건에 맞는 항목만 표시된다  
그리고: 필터를 하나 선택해도 다른 값으로 바꿀 수 있도록 선택지는 전체 데이터를 기준으로 유지된다.

조건: 관리 표에 11건 이상의 데이터가 있다  
동작: 하단의 페이지 번호나 다음 버튼을 누른다  
결과: 다음 페이지의 항목이 같은 정렬 기준으로 이어서 표시된다  
그리고: 총 건수와 페이지당 10·20·30개 선택은 데이터가 10건 이하여도 항상 표시된다.

조건: 운영자가 3페이지에서 페이지당 개수를 바꾸거나 검색어·필터를 바꾼다  
동작: 목록을 다시 계산한다  
결과: 1페이지부터 표시된다.

조건: 이름이 같은 항목이 여러 개 있다  
동작: 페이지를 넘기거나 다시 조회한다  
결과: 보조 기준(id)으로 순서가 고정되어 페이지 경계에서 중복이나 누락이 생기지 않는다.

조건: 선생님이 11명 이상이다  
동작: 급여표를 만들거나 원생 등록의 담당 선생님, 교재 출고의 원생 선택지를 연다  
결과: 선택지와 급여 계산은 페이지로 자르지 않고 전체 대상을 가나다순으로 사용한다.

조건: 퇴원 원생 또는 퇴사 선생님의 상세를 연다  
동작: 삭제하려 한다  
결과: 삭제 버튼은 비활성이며 "결제·회차권·급여 기록을 보존하기 위해 삭제할 수 없습니다. 보관 상태로 유지됩니다."를 안내한다.

조건: 운영자가 입출금 내역이나 날짜 메모의 삭제를 누른다  
동작: 확인 창을 취소한다  
결과: 삭제되지 않는다  
그리고: 확인하면 한 번만 삭제 요청이 전송된다.

조건: 데이터를 불러오지 못하거나 저장에 실패한다  
동작: 오류를 표시한다  
결과: `permission denied` 같은 원문 대신 무엇이 문제이고 어떻게 하면 되는지를 한국어로 안내한다.

## 홈 화면과 접근 안내

조건: 로그인한 역할이 홈을 연다  
동작: 첫 화면을 확인한다  
결과: 그 역할이 볼 수 있는 메뉴로 이동하는 바로가기만 표시되고 가짜 건수나 개발 메모는 없다.

조건: 선생님이 수입 관리 같은 숨겨진 메뉴의 주소로 직접 접근한다  
동작: 화면을 연다  
결과: 목록을 불러오지 않고 "이 화면을 볼 권한이 없습니다" 안내와 홈 링크를 표시한다.

조건: 로그인 사용자가 학원 멤버십이 없거나 네트워크가 끊겨 학원 정보를 불러오지 못한다  
동작: 화면을 연다  
결과: 로그인 폼 대신 원인과 "다시 시도" 버튼을 표시한다.

## 역할별 로그인과 권한

조건: 사용자가 현재 학원에 활성 owner 멤버십을 가지고 있다  
동작: 세션 역할을 해석한다  
결과: owner로 판단하고 전체 운영 기능 접근을 허용한다.

조건: 사용자가 현재 학원에 활성 desk 멤버십을 가지고 있다  
동작: 기능 접근 권한을 확인한다  
결과: 원생, 일정, 거래처 같은 일상 운영 기능은 허용한다  
그리고: 수입 관리는 별도 설정이 없으면 허용하지 않는다.

조건: 선생님이 배정된 원생과 본인 급여를 확인한다  
동작: 기능 접근 권한을 확인한다  
결과: 배정 원생과 본인 급여만 허용한다  
그리고: 거래처와 수입 관리 메뉴는 숨긴다.

조건: 사용자가 현재 학원에 활성 멤버십이 없다  
동작: 운영 기능 접근 권한을 확인한다  
결과: anonymous로 판단하고 운영 기능 접근을 거부한다.

## 학원 피아노 레슨표

조건: 운영자가 레슨 시간표 메뉴를 연다
동작: 학원 레슨표 탭을 확인한다
결과: 월간 캘린더, 날짜 클릭 출석 다이얼로그, 메모지, 미등원 인원 액션이 함께 표시된다
그리고: 좁은 모바일 화면에서도 캘린더는 월간 7열 구조를 유지한다.

조건: 원생이 학원 수업 요일을 월요일과 수요일로 등록했다  
동작: 해당 월의 레슨표를 생성한다  
결과: 해당 월의 모든 월요일과 수요일에 원생 일정이 표시된다.

조건: 다른 학원, 비활성 수강, 개인레슨 수강 정보가 섞여 있다  
동작: 현재 학원의 학원 수업 레슨표를 생성한다  
결과: 현재 학원의 활성 학원 수업 수강 정보만 일정으로 표시된다.

조건: 학원 수업 일정을 같은 월 안에서 다른 날짜와 시간으로 이동한다  
동작: 일정 이동을 저장한다  
결과: 이동된 일정만 변경된다  
그리고: 원생의 기본 수업 요일은 변경되지 않는다.

조건: 학원 수업 일정을 다른 월로 이동하려 한다  
동작: 일정 이동을 저장한다  
결과: 이동을 막고 같은 월 안에서만 가능하다는 오류를 표시한다.

조건: 운영자가 특정 날짜를 선택한다  
동작: 일별 출석 모달을 연다  
결과: 해당 날짜에 출석 예정인 원생만 시간과 이름 순서로 표시된다.

조건: 운영자가 일별 출석 모달에서 원생 한 명을 결석 처리한다  
동작: 결석 사유와 처리 시간을 저장한다  
결과: 해당 원생은 결석 상태가 된다  
그리고: 보강 또는 패스 확정을 기다리는 결석 인원 목록에 표시된다.

조건: 운영자가 일별 출석 모달에서 전체 출석을 누른다  
동작: 해당 날짜의 모든 예정 원생을 출석 처리한다  
결과: 결석 인원 목록은 비어 있다.

조건: 운영자가 일별 출석 모달에서 전체 결석을 누른다  
동작: 결석 사유와 처리 시간을 저장한다  
결과: 해당 날짜의 모든 예정 원생이 결석 인원 목록으로 이동한다.

조건: 운영자가 학원 수업 일정을 삭제한다  
동작: 삭제 사유를 입력하고 저장한다  
결과: 일정은 삭제 상태로 기록된다  
그리고: 원생의 기본 반복 수업 요일은 변경되지 않는다.

조건: 운영자가 학원 수업 일정을 삭제한다
동작: 삭제 사유를 비워 두고 저장한다
결과: 삭제를 막고 사유를 입력하라는 안내를 표시한다.

조건: 출석 또는 결석이 이미 처리된 일정이 있다
동작: 해당 일정을 삭제하려 한다
결과: 삭제를 막고 출결 초기화 후 삭제하라는 안내를 표시한다.

조건: 운영자가 데스크톱에서 일정을 같은 달의 다른 날짜로 끌어다 놓는다
동작: 드롭한다
결과: 해당 월의 그 일정만 이동하고 원생 기본 요일은 바뀌지 않는다
그리고: 다른 달로 끌어다 놓으면 이동하지 않고 같은 달 안에서만 이동할 수 있다는 안내를 표시한다.

조건: 운영자가 요일별 인원확인 카드를 연다
동작: 선택한 달의 정규 일정을 확인한다
결과: 월~금 요일별 원생 수와 이름, 전체(중복 제외) 인원이 표시된다.

조건: 운영자가 출석확인에서 원생별 등원/결석을 고르고 확인 전 상태다
동작: 취소를 누른다
결과: 선택은 버려지고 저장되지 않는다.

조건: 운영자가 출석확인에서 원생별 등원/결석을 고른다
동작: 확인을 누른다
결과: 선택한 상태가 한 번에 저장된다
그리고: 결석으로 저장된 원생은 결석인원 목록에 표시된다.

조건: 마감된(확인 완료) 날짜의 출결을 고치려 한다
동작: 출결 초기화를 누른다
결과: 해당 날짜의 출결이 대기 상태로 돌아가 다시 선택할 수 있다.

조건: 선생님 역할로 학원 레슨표를 연다
동작: 화면을 확인한다
결과: 출석·이동·삭제·보강·초기화·일정 추가 버튼은 보이지 않고 조회 전용 안내가 표시된다.

## 회차권 차감

조건: 개인레슨 원생에게 피아노 회차권 잔여 4회가 있다  
동작: 해당 수업의 출석을 확인한다  
결과: 잔여 회차는 3회가 된다  
그리고: 차감 기록은 수업일, 학원, 원생, 악기와 함께 기록된다.

조건: 개인레슨 원생이 결석 처리된다  
동작: 결석 상태를 저장한다  
결과: 잔여 회차는 변경되지 않는다.

조건: 원생이 수업 일정에만 등록되어 있다  
동작: 실제 출석 확인이 아직 처리되지 않았다  
결과: 잔여 회차는 변경되지 않는다.

조건: 같은 수업 출석 확인이 이미 차감 처리되었다  
동작: 같은 수업을 다시 출석 처리한다  
결과: 잔여 회차는 중복 차감되지 않는다.

조건: 학원 A의 회차권이 있다  
동작: 학원 B의 출석 기록으로 차감을 시도한다  
결과: 차감은 거부된다.

## 회차권 재등록과 상태 표시

조건: 운영자가 회차권을 등록한다
동작: 원생, 악기, 부여 회수, 사용 기한(일수), 등록일을 입력한다
결과: 입력 기준 만료일이 `등록일 + 사용 기한`으로 계산되어 미리 보인다
그리고: 부여 회수 기본값은 4회, 사용 기한 기본값은 30일이며 결제 금액을 비워도 등록된다.

조건: 회차권 등록에서 결제 금액을 입력하고 원장 권한이 있다
동작: 등록한다
결과: 수입 내역에 결제 금액이 함께 기록된다.

조건: 데스크 직원이 회차권 등록을 연다
동작: 부여 회수와 사용 기한을 입력해 등록한다
결과: 결제 금액 입력칸은 없고 회차권은 등록된다. 우회 요청에 양수 결제 금액이 있으면 서버가 등록과 원장 기록을 함께 거부한다.

조건: 같은 학원, 원생, 악기의 활성 회차권 잔여 3회가 있다  
동작: 같은 범위로 10회 회차권을 사용 기한 30일로 등록한다
결과: 총 부여 회수와 잔여 회수에 10회가 더해진다  
그리고: 만료일은 기존 만료일과 `등록일 + 30일` 중 늦은 날로 갱신되고 결제 금액은 누적된다.
그리고: 새 등록의 회수·기간·결제와 연결 원장은 구매 단위로 따로 남으며, 등록일이 직전 등록일보다 앞서면 저장되지 않는다.

조건: 기존 회차권 만료일이 새 등록일과 사용 기한으로 계산한 날짜보다 늦다
동작: 같은 원생·악기로 재등록한다
결과: 기존 만료일이 단축되지 않고 새 등록 이력에도 유지된 만료일이 기록된다.

조건: 이전 회차권 만료 후 며칠 뒤 같은 악기로 재등록했다
동작: 만료 후 새 등록 전 공백 날짜의 개인레슨을 출석 처리한다
결과: 회차가 남아 있어도 그 수업일의 차감은 거부되고 출석 상태도 바뀌지 않는다.

조건: 회차권 목록을 연다
동작: 열을 확인한다
결과: 총 부여, 사용(총 부여−잔여), 잔여, 등록일, 만료일, 서울 기준 남은 일수, 상태가 표시된다. 만료 당일은 `0일 남음 · 오늘까지 사용 가능`으로 표시된다.

조건: 잔여 회차가 2회 이하인 회차권이 있다
동작: 목록을 확인한다
결과: 잔여 회수가 눈에 띄게 강조된다.

결과: 읽지 않음 표시가 해제된다.

동작: 화면을 새로고침한다  
결과: 메모 패널은 기본 위치와 기본 크기로 초기화되고 내용은 월별로 유지된다.

조건: 새 내용이 저장되거나 사유서 자동 기록이 추가되었다
동작: 메모 표시를 확인한다
결과: "미확인" 표시가 뜨고 "확인" 버튼을 눌러야만 해제된다.

조건: 선생님 역할로 레슨 시간표를 연다
동작: 학원 레슨표를 확인한다
결과: 월별 메모는 보이지 않는다.

## 원생 등록

조건: 새 원생이 악기, 선생님, 수업 형태, 수업 요일, 수강료, 할인과 함께 등록된다  
동작: 원생을 저장한다  
결과: 원생은 원생 목록에 표시된다  
그리고: 반복 수업 일정 데이터가 준비된다  
그리고: 학원 고정 수입에 최종 수강료가 반영된다.

조건: 학원 수업 악기 등록에서 레슨비와 할인 합계가 최종 수강료와 맞지 않는다  
동작: 원생을 저장한다  
결과: 저장을 막고 수강료 검증 오류를 표시한다.

조건: 학원 수업 악기 등록에서 수업 요일 또는 시간이 비어 있다  
동작: 원생을 저장한다  
결과: 저장을 막고 일정 기준 정보가 필요하다고 표시한다.

## 원생 목록

조건: 운영자가 원생 목록을 연다  
동작: 현재 학원의 원생 목록을 조회한다  
결과: 현재 학원의 원생만 이름 가나다순으로 표시된다.

조건: 운영자가 원생 목록에서 검색어를 입력한다  
동작: 이름, 담당 선생님, 악기, 정기 요일과 대조한다  
결과: 검색어가 포함된 원생만 표시된다.

조건: 운영자가 원생 목록에서 담당 선생님, 악기, 정기 요일 필터를 선택한다  
동작: 목록을 다시 계산한다  
결과: 선택한 필터 조건을 모두 만족하는 원생만 표시된다.

## 거래처 등록

조건: 운영자가 거래처를 등록한다  
동작: 거래처명, 연락처, 종류, 비고를 입력하고 저장한다  
결과: 현재 학원 거래처로 등록된다.

조건: 거래처명 또는 종류가 비어 있다  
동작: 거래처를 저장하려 한다  
결과: 저장을 막고 필수 입력 오류를 표시한다.

조건: 등록된 거래처가 있다  
동작: 목록에서 수정을 누르고 거래처명, 연락처, 종류, 비고를 바꿔 저장한다  
결과: 같은 거래처 정보가 갱신되고 목록에 반영된다.

## 선생님 등록

조건: 운영자가 선생님을 등록한다  
동작: 담당 파트, 연락처, 등록일, 주민등록번호 보안 참조, 급여 형태를 입력하고 저장한다  
결과: 현재 학원 선생님으로 등록된다  
그리고: 주민등록번호 원문은 도메인 기록에 남기지 않고 암호화 참조와 마스킹 값만 기록한다.

조건: 선생님명, 담당 파트, 연락처, 주민등록번호 보안 참조 또는 마스킹 값이 비어 있다  
동작: 선생님을 저장하려 한다  
결과: 저장을 막고 필수 입력 오류를 표시한다.

조건: 지원하지 않는 급여 형태를 선택했다  
동작: 선생님을 저장하려 한다  
결과: 저장을 막고 급여 형태 오류를 표시한다.

## 원생 상태 전환

조건: 재원 원생이 있다  
동작: 휴원 처리한다  
결과: 확인 절차를 요구하고 휴원 상태로 이동한다.

조건: 휴원 원생이 있다  
동작: 재원 처리한다  
결과: 확인 절차를 요구하고 재원 상태로 복구한다.

조건: 휴원 원생이 있다  
동작: 퇴원 처리한다  
결과: 확인 절차를 요구하고 퇴원일을 기록한다.

조건: 퇴원 원생이 있다  
동작: 휴원 처리하려 한다  
결과: 직접 전환을 막고 먼저 재원 처리가 필요하다고 안내한다.

## 원생 보관 정책

조건: 퇴원 원생의 퇴원일이 기록되어 있다  
동작: 보관 만료일을 계산한다  
결과: 퇴원일로부터 30일 뒤 삭제 가능일과 남은 일수를 표시한다.

조건: 퇴원 원생의 30일 보관 기간이 지났다  
동작: 보관 상태를 계산한다  
결과: 삭제 가능 상태만 표시하고 실제 삭제 방식은 별도 정책 결정 전까지 실행하지 않는다.

## 교재 판매

조건: 교재 재고 수량이 2개다  
동작: 교재 1권을 원생에게 출고한다  
결과: 재고 수량은 1개가 된다  
그리고: 해당 판매는 결제 대기 상태가 된다.

조건: 교재 재고 수량이 1개다  
동작: 교재 1권을 원생에게 출고한다  
결과: 재고 수량은 0개가 된다  
그리고: 재고 기록은 목록에 계속 표시된다.

조건: 다른 학원의 재고가 있다  
동작: 현재 학원의 원생에게 출고하려 한다  
결과: 출고를 막고 학원 범위 오류를 표시한다.

조건: 출고된 교재의 결제를 확인한다  
동작: 결제일을 저장한다  
결과: 판매는 결제 완료 내역에 표시된다  
그리고: 결제일 기준 수입 ledger 항목이 생성된다.

조건: 이미 결제 완료된 교재 판매가 있다  
동작: 다시 결제 완료 처리한다  
결과: 중복 처리를 막는다.

## 수입 관리

조건: 월별 고정 수입 기준이 있다  
동작: 해당 월의 수강료 snapshot을 생성한다  
결과: 각 항목은 미납 상태로 초기화된다.

조건: 다른 학원, 비활성 수강, 미래 시작 고정 수입 기준이 있다  
동작: 현재 학원의 이번 달 snapshot을 생성한다  
결과: 현재 학원에서 이번 달 적용 가능한 활성 기준만 포함된다.

조건: 미납 상태의 수강료 항목이 있다  
동작: 수납 완료 처리한다  
결과: 상태는 수납 완료가 되고 수입 ledger 항목이 생성된다.

조건: 미납 상태의 수강료 항목이 있다  
동작: 미납 버튼을 누른다  
결과: 미납 목록 항목이 생성된다.

## 입출입 내역

조건: 원장 또는 허용된 데스크 직원이 수동 수입 또는 지출을 입력한다  
동작: 금액, 발생일, 설명을 저장한다  
결과: 수동 ledger 항목이 생성된다.

조건: 권한 없는 사용자가 수동 수입 또는 지출을 입력한다  
동작: 저장하려 한다  
결과: 수동 입력이 거부된다.

## 전체 수입 그래프

조건: 운영자가 특정 연도의 전체 수입 그래프를 본다  
동작: 현재 학원의 ledger를 집계한다  
결과: 월별 전체 악기 수입, 개별 악기 수입, 학원 수입, 지출, 순수입이 표시된다  
그리고: 연간 수입·지출·순수익 합계가 함께 표시되고 분류별 수입에는 지출이 섞이지 않는다.

## 급여 지급

조건: 비율제 선생님이 이번 달 완료된 수업을 담당했다  
동작: 급여를 계산한다  
결과: 기본 급여는 수업별 수강료와 선생님 비율을 기준으로 계산된다  
그리고: 세후 급여는 3.3% 원천징수를 반영한다.

조건: 비율제 급여의 원천징수 원 단위 처리 정책이 설정되어 있다  
동작: 급여를 계산한다  
결과: 설정된 반올림, 올림, 내림 정책으로 원천징수액을 계산한다.

조건: 급여 지급이 확정된다  
동작: 급여를 지급 완료로 표시한다  
결과: 입출입 ledger에 지출 항목이 생성된다.

조건: 이미 지급 완료된 급여가 있다  
동작: 다시 지급 완료 처리한다  
결과: 중복 처리를 막는다.

조건: 월급제 선생님이 등록되어 있다  
동작: 월 급여를 계산한다  
결과: 월 고정 급여에서 3.3% 원천징수를 반영한 세후 급여가 계산된다.

조건: 시급제 선생님이 등록되어 있다  
동작: 월 근무 시간과 시급으로 급여를 계산한다  
결과: `시급 * 근무 시간`에서 3.3% 원천징수를 반영한 세후 급여가 계산된다.

조건: 월급제에 월 고정 급여가 없거나 시급제에 근무 시간이 없다  
동작: 급여를 계산하려 한다  
결과: 급여 유형별 필수 조건 오류를 표시한다.

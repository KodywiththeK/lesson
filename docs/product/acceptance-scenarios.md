# 인수 시나리오

이 문서는 TDD 시작점으로 사용한다. 시나리오가 구현되면 `docs/product/traceability-matrix.md`에 테스트와 구현 위치를 연결한다.

## 브랜드와 검색 노출

조건: 로그인하지 않은 방문자가 공식 주소의 첫 화면을 연다
동작: 페이지 제목과 공유 미리보기를 확인한다
결과: `마디마디`와 “모든 수업의 마디마다, 더 편리한 음악학원 관리”가 제목·설명에 포함되고 제공된 썸네일이 보인다.

조건: 방문자가 브라우저 탭이나 기기의 사이트 아이콘을 확인한다
동작: 공개 화면을 열고 아이콘 파일과 manifest를 조회한다
결과: 제공된 파비콘·Apple 아이콘·Android 아이콘이 각각 페이지와 manifest에 연결되어 있다.

조건: 운영자가 데스크톱 사이드바 또는 작은 화면의 메뉴를 연다
동작: 현재 학원명을 확인한다
결과: 마디마디 로고가 학원명 위에 보이며 두 이름이 구분된다.

조건: 운영자가 데스크톱 사이드바나 모바일 메뉴를 아래로 스크롤한다
동작: 같은 브라우저 탭에서 다른 메뉴로 이동하거나 모바일 메뉴를 닫았다 다시 연다
결과: 각 메뉴의 스크롤 위치가 이전 위치로 복원된다
그리고: 본문 스크롤 위치와 다른 브라우저 탭에는 영향을 주지 않는다.

조건: 운영자가 홈 또는 하위 페이지를 연다
동작: 데스크톱·모바일에서 상위 메뉴를 호버하거나 화살표 버튼을 클릭한다
결과: 처음에는 현재 페이지의 메뉴만 펼쳐진다. 호버만으로는 열리지 않고 화살표 버튼을 클릭하면 열거나 닫을 수 있다. 다른 하위 페이지로 이동하면 새 경로의 메뉴만 기본으로 펼쳐진다.

조건: 검색 엔진이 사이트맵과 로그인 뒤 운영 경로를 조회한다
동작: `/sitemap.xml`과 운영 화면의 응답 헤더를 확인한다
결과: 사이트맵에는 공개 진입점만 있고 운영 경로에는 `noindex, nofollow`가 있다.

## 공통 목록 동작

조건: 운영자가 원생·선생님·회차권·교재·입출금 목록을 작은 화면에서 연다
동작: 화면을 1024px 표, 768~1023px 행 중심 배치, 481~767px 카드 2열, 480px 이하 카드 1열로 바꿔 본다
결과: 같은 데이터·상태·작업 버튼이 보이고 페이지 전체 가로 넘침이나 잘린 필터가 없다.

조건: 운영자가 원생, 선생님, 거래처, 교재, 수입 내역 같은 업무 목록을 연다  
동작: 별도 페이지 크기를 선택하지 않는다  
결과: 목록은 기본 10개 단위로 표시된다  
그리고: 10개, 20개, 30개 단위로 전환할 수 있다.

조건: 업무 목록에 한글 이름 데이터가 섞여 있다  
동작: 목록을 기본 정렬로 조회한다  
결과: 이름은 `ko-KR` 기준 가나다 순서와 숫자 인식 순서로 정렬된다.

조건: 운영자가 목록 검색어를 입력한다  
동작: 이름, 악기, 담당 선생님 같은 지정 검색 필드와 대조한다  
결과: 검색어가 포함된 항목만 표시된다.

조건: 운영자가 담당 선생님, 악기, 정기 요일 같은 필터를 선택한다  
동작: 목록을 다시 계산한다  
결과: 선택한 필터 조건에 맞는 항목만 표시된다  
그리고: 필터를 하나 선택해도 다른 값으로 바꿀 수 있도록 선택지는 전체 데이터를 기준으로 유지된다.

조건: 관리 표에 11건 이상의 데이터가 있다  
동작: 하단의 페이지 번호나 다음 버튼을 누른다  
결과: 다음 페이지의 항목이 같은 정렬 기준으로 이어서 표시된다  
그리고: 총 건수와 페이지당 10·20·30개 선택은 데이터가 10건 이하여도 항상 표시된다.

조건: 운영자가 3페이지에서 페이지당 개수를 바꾸거나 검색어·필터를 바꾼다  
동작: 목록을 다시 계산한다  
결과: 1페이지부터 표시된다.

조건: 이름이 같은 항목이 여러 개 있다  
동작: 페이지를 넘기거나 다시 조회한다  
결과: 보조 기준(id)으로 순서가 고정되어 페이지 경계에서 중복이나 누락이 생기지 않는다.

조건: 선생님이 11명 이상이다  
동작: 급여표를 만들거나 원생 등록의 담당 선생님, 교재 출고의 원생 선택지를 연다  
결과: 선택지와 급여 계산은 페이지로 자르지 않고 전체 대상을 가나다순으로 사용한다.

조건: 퇴원 원생 또는 퇴사 선생님의 상세를 연다  
동작: 삭제하려 한다  
결과: 삭제 버튼은 비활성이며 "결제·회차권·급여 기록을 보존하기 위해 삭제할 수 없습니다. 보관 상태로 유지됩니다."를 안내한다.

조건: 운영자가 입출금 내역이나 날짜 메모의 삭제를 누른다  
동작: 확인 창을 취소한다  
결과: 삭제되지 않는다  
그리고: 확인하면 한 번만 삭제 요청이 전송된다.

조건: 데이터를 불러오지 못하거나 저장에 실패한다  
동작: 오류를 표시한다  
결과: `permission denied` 같은 원문 대신 무엇이 문제이고 어떻게 하면 되는지를 한국어로 안내한다.

## 홈 화면과 접근 안내

조건: 로그인한 역할이 홈을 연다  
동작: 첫 화면을 확인한다  
결과: 그 역할이 볼 수 있는 메뉴로 이동하는 바로가기만 표시되고 가짜 건수나 개발 메모는 없다.

조건: 선생님이 수입 관리 같은 숨겨진 메뉴의 주소로 직접 접근한다  
동작: 화면을 연다  
결과: 목록을 불러오지 않고 "이 화면을 볼 권한이 없습니다" 안내와 홈 링크를 표시한다.

조건: 로그인 사용자가 학원 멤버십이 없거나 네트워크가 끊겨 학원 정보를 불러오지 못한다  
동작: 화면을 연다  
결과: 로그인 폼 대신 원인과 "다시 시도" 버튼을 표시한다.

## 역할별 로그인과 권한

조건: 기존 이메일·비밀번호 계정이 있다
동작: 일반 로그인 화면에서 이메일과 비밀번호로 로그인한다
결과: 기존 사용자 ID의 활성 학원 멤버십으로 운영 화면에 들어간다
그리고: 로컬 개발 환경의 자동 입력값은 개발 화면에만 보인다.
그리고: 이 로그인 수단은 기존 원장 카카오 전환 검증과 폐기 작업이 끝날 때까지만 유지한다.

조건: 이메일이 서로 다른 기존 원장 계정과 카카오 계정을 연결한다
동작: 기존 원장 계정으로 먼저 로그인하고 카카오 identity를 수동 연결한다
결과: 같은 사용자 ID에 카카오 identity가 추가되고 기존 학원·멤버십 참조가 유지된다
그리고: 일반 카카오 로그인을 먼저 시도해 별도 사용자를 만들지 않는다.

조건: 기존 원장이 카카오 계정을 연결하고 로그아웃한 뒤 일반 카카오 로그인으로 같은 학원을 열었다
동작: 임시 정리 화면에서 확인 대화상자를 거쳐 기존 이메일 로그인 정보를 삭제한다
결과: 원장 사용자 ID·학원 데이터는 유지되고 비밀번호 해시가 제거된 뒤 이메일 identity가 해제된다
그리고: 다른 사용자, 카카오 미연결 계정, 이메일로 로그인한 세션에서는 비밀번호 제거 RPC를 실행할 수 없다.

조건: 카카오 인증은 됐지만 활성 학원 멤버십이 없다
동작: 학원 시작하기 화면에서 로그아웃한다
결과: 앱의 Supabase 세션과 학원별 캐시가 정리되고 로그인 화면이 나타난다.

조건: 가입 신청이 대기 중이고 원장이 반려했다
동작: 신청자가 학원 시작하기 화면에서 승인 상태를 새로고침한다
결과: 신청 이력도 다시 조회해 반려 상태를 표시한다. 다른 활성 학원이 있는 계정은 현재 화면에 남아 신청 결과를 확인할 수 있다.

조건: 사용자가 현재 학원에 활성 owner 멤버십을 가지고 있다  
동작: 세션 역할을 해석한다  
결과: owner로 판단하고 전체 운영 기능 접근을 허용한다.

조건: 사용자가 현재 학원에 활성 desk 멤버십을 가지고 있다  
동작: 기능 접근 권한을 확인한다  
결과: 원생, 일정, 거래처 같은 일상 운영 기능은 허용한다  
그리고: 수입 관리는 별도 설정이 없으면 허용하지 않는다.

조건: 선생님이 배정된 원생과 본인 급여를 확인한다  
동작: 기능 접근 권한을 확인한다  
결과: 배정 원생과 본인 급여만 허용한다  
그리고: 거래처와 수입 관리 메뉴는 숨긴다.

조건: 사용자가 현재 학원에 활성 멤버십이 없다  
동작: 운영 기능 접근 권한을 확인한다  
결과: anonymous로 판단하고 운영 기능 접근을 거부한다.

## 학원 피아노 레슨표

조건: 운영자가 레슨 시간표 메뉴를 연다
동작: 학원 레슨표 탭을 확인한다
결과: 월간 캘린더, 날짜 클릭 출석 다이얼로그, 메모지, 미등원 인원 액션이 함께 표시된다
그리고: 좁은 모바일 화면에서도 캘린더는 월간 7열 구조를 유지한다.

조건: 원생이 학원 수업 요일을 월요일과 수요일로 등록했다  
동작: 해당 월의 레슨표를 생성한다  
결과: 해당 월의 모든 월요일과 수요일에 원생 일정이 표시된다.

조건: 다른 학원, 비활성 수강, 개인레슨 수강 정보가 섞여 있다  
동작: 현재 학원의 학원 수업 레슨표를 생성한다  
결과: 현재 학원의 활성 학원 수업 수강 정보만 일정으로 표시된다.

조건: 학원 수업 일정을 같은 월 안에서 다른 날짜와 시간으로 이동한다  
동작: 일정 이동을 저장한다  
결과: 이동된 일정만 변경된다  
그리고: 원생의 기본 수업 요일은 변경되지 않는다.

조건: 학원 수업 일정을 다른 월로 이동하려 한다  
동작: 일정 이동을 저장한다  
결과: 이동을 막고 같은 월 안에서만 가능하다는 오류를 표시한다.

조건: 운영자가 특정 날짜를 선택한다  
동작: 일별 출석 모달을 연다  
결과: 해당 날짜에 출석 예정인 원생만 시간과 이름 순서로 표시된다.

조건: 운영자가 일별 출석 모달에서 원생 한 명을 결석 처리한다  
동작: 결석 사유와 처리 시간을 저장한다  
결과: 해당 원생은 결석 상태가 된다  
그리고: 보강 또는 패스 확정을 기다리는 결석 인원 목록에 표시된다.

조건: 운영자가 일별 출석 모달에서 전체 출석을 누른다  
동작: 해당 날짜의 모든 예정 원생을 출석 처리한다  
결과: 결석 인원 목록은 비어 있다.

조건: 운영자가 일별 출석 모달에서 전체 결석을 누른다  
동작: 결석 사유와 처리 시간을 저장한다  
결과: 해당 날짜의 모든 예정 원생이 결석 인원 목록으로 이동한다.

조건: 운영자가 학원 수업 일정을 삭제한다  
동작: 삭제 사유를 입력하고 저장한다  
결과: 일정은 삭제 상태로 기록된다  
그리고: 원생의 기본 반복 수업 요일은 변경되지 않는다.

조건: 운영자가 학원 수업 일정을 삭제한다
동작: 삭제 사유를 비워 두고 저장한다
결과: 삭제를 막고 사유를 입력하라는 안내를 표시한다.

조건: 출석 또는 결석이 이미 처리된 일정이 있다
동작: 해당 일정을 삭제하려 한다
결과: 삭제를 막고 출결 초기화 후 삭제하라는 안내를 표시한다.

조건: 운영자가 데스크톱에서 일정을 같은 달의 다른 날짜로 끌어다 놓는다
동작: 드롭한다
결과: 해당 월의 그 일정만 이동하고 원생 기본 요일은 바뀌지 않는다
그리고: 다른 달로 끌어다 놓으면 이동하지 않고 같은 달 안에서만 이동할 수 있다는 안내를 표시한다.

조건: 운영자가 요일별 인원확인 카드를 연다
동작: 선택한 달의 정규 일정을 확인한다
결과: 월~금 요일별 원생 수와 이름, 전체(중복 제외) 인원이 표시된다.

조건: 운영자가 출석확인에서 원생별 등원/결석을 고르고 저장 전 상태다
동작: 닫기를 누른다
결과: 선택은 버려지고 저장되지 않는다.

조건: 운영자가 출석확인에서 원생별 등원/결석을 고른다
동작: 출석 저장을 누른다
결과: 선택한 상태가 한 번에 저장된다

## 회차권 재등록과 상태 표시

조건: 운영자가 회차권을 등록한다
동작: 원생, 악기, 부여 회수, 사용 기한(일수), 등록일을 입력한다
결과: 입력 기준 만료일이 `등록일 + 사용 기한`으로 계산되어 미리 보인다
그리고: 부여 회수 기본값은 4회, 사용 기한 기본값은 30일이며 결제 금액을 비워도 등록된다.

조건: 회차권 등록에서 결제 금액을 입력하고 원장 권한이 있다

조건: 데스크 직원이 회차권 등록을 연다
동작: 부여 회수와 사용 기한을 입력해 등록한다
결과: 결제 금액 입력칸은 없고 회차권은 등록된다. 우회 요청에 양수 결제 금액이 있으면 서버가 등록과 원장 기록을 함께 거부한다.

조건: 같은 학원, 원생, 악기의 활성 회차권 잔여 3회가 있다

결과: 총 부여 회수와 잔여 회수에 10회가 더해진다  
그리고: 만료일은 기존 만료일과 `등록일 + 30일` 중 늦은 날로 갱신되고 결제 금액은 누적된다.
그리고: 새 등록의 회수·기간·결제와 연결 원장은 구매 단위로 따로 남으며, 등록일이 직전 등록일보다 앞서면 저장되지 않는다.

조건: 기존 회차권 만료일이 새 등록일과 사용 기한으로 계산한 날짜보다 늦다
동작: 같은 원생·악기로 재등록한다
결과: 기존 만료일이 단축되지 않고 새 등록 이력에도 유지된 만료일이 기록된다.

조건: 이전 회차권 만료 후 며칠 뒤 같은 악기로 재등록했다
동작: 만료 후 새 등록 전 공백 날짜의 개인레슨을 출석 처리한다
결과: 회차가 남아 있어도 그 수업일의 차감은 거부되고 출석 상태도 바뀌지 않는다.

조건: 회차권 목록을 연다
동작: 열을 확인한다
결과: 총 부여, 사용(총 부여−잔여), 잔여, 등록일, 만료일, 서울 기준 남은 일수, 상태가 표시된다. 만료 당일은 `0일 남음 · 오늘까지 사용 가능`으로 표시된다.

조건: 잔여 회차가 2회 이하인 회차권이 있다
동작: 목록을 확인한다
결과: 잔여 회수가 눈에 띄게 강조된다.

조건: 만료일이 며칠 안으로 다가온 회차권이 있다
동작: 목록을 확인한다
결과: "만료 임박" 상태는 표시하지 않으며 만료일이 지난 회차권만 "만료"로 표시한다.

## 회차권 관리 권한

조건: 원장이 회차권 잔여 회수를 수동 수정한다

결과: 잔여 회수가 조정된다

조건: 권한 없는 사용자가 회차권 잔여 회수를 수동 수정한다

조건: 학원레슨표에서 8월에 여러 날짜의 결석이 있다

그리고: 그날 등원 인원이 적은 순(같으면 결석일에 가까운 날)으로 최대 5개가 `8/14 (금) · 3명` 형식으로 보이고 1순위가 기본 선택된다
그리고: 제목 옆 ⓘ 툴팁이 기준 3가지를 설명하고 달력에서 직접 다른 날을 고를 수 있다.

동작: 확인을 누른다
결과: "최종확인하시겠습니까?"가 표시되고 확인해야 처리가 확정된다.

동작: 보강 날짜를 입력해 보강으로 최종확인한다

그리고: 원본 수업은 결석 기록으로 남고 회차권은 차감·복구되지 않는다
그리고: 보강 시간을 비우면 원본 시간으로 저장하되 시간은 표시하지 않는다.

조건: 원생이 학원 수업에서 결석 처리되었다  
동작: 패스로 최종확인한다
결과: 보강 일정은 생기지 않고 회차권은 차감되지 않는다.

동작: 화면을 새로고침한다
결과: 해당 결석은 결석인원 목록에 `보강 완료` 또는 `패스 완료`로 표시되고 결석확인·취소 버튼이 없으며 같은 결석을 다시 처리할 수 없다(보강 이중 생성 방지).

그리고: 학원 고정 수입에 최종 수강료가 반영된다.

조건: 학원레슨 요일의 시작 시간만 입력했다
동작: 원생 등록 또는 수정을 저장하려 한다
결과: 시작·종료 시간을 함께 입력하라는 오류가 보이고 저장되지 않는다.

조건: 학원 수업 악기 등록에서 레슨비와 할인 합계가 최종 수강료와 맞지 않는다

조건: 학원 수업 악기 등록에서 담당 선생님 또는 수업 요일이 비어 있다
동작: 원생을 저장한다  
결과: 저장을 막고 일정 기준 정보가 필요하다고 표시한다.

조건: 원생을 수정하면서 학원 수업의 일부 요일 시간을 비우거나 담당 선생님을 없앴다

결과: 버튼이 비활성이고 이유 문구가 보이며, 서버도 같은 이유로 거부한다(정기 일정이 조용히 사라지지 않는다).

조건: 요일마다 시간이 다른 원생(월 15:00, 목 17:00)을 수정한다
동작: 수정 폼을 연다
결과: 요일별 시작·종료 시간이 그대로 보이고, 저장하면 요일별 시간과 정기 일정이 함께 갱신된다.

조건: 피아노와 바이올린을 함께 배우는 원생의 수정 폼을 연다
동작: 바이올린 담당 선생님·요일·레슨비를 바꾸고 저장한다
결과: 악기별 섹션(`피아노 …`, `바이올린 …`)이 모두 보이고 바이올린만 갱신되며 피아노 정보는 그대로다. 두 악기를 모두 고치면 두 악기가 한 번에(한 트랜잭션으로) 저장된다.

조건: 복수 악기 원생을 저장하는데 서버가 일부 변경을 거부한다(예: 같은 악기·수업 형태 중복)

결과: 저장되지 않았다는 안내와 이유가 보이고 어떤 변경도 저장되지 않으며(이름·기본 정보 포함) 폼은 입력값을 유지한 채 열려 있어 고쳐서 다시 저장할 수 있다.

조건: 원생의 수정 폼에서 [악기 추가]를 누른다
동작: 첼로·학원 수업·요일별 시간·레슨비를 입력하고 수강 시작일을 기본값(오늘)으로 두고 저장한다
결과: 악기가 추가되어 상세에 보이고 시작일 이후의 정기 일정이 생기며, 이미 수강 중인 악기·수업 형태 조합은 선택지에 없다.

조건: 수강 중인 악기가 둘 이상인 원생의 한 악기에서 [수강 종료]를 누르고 확인한다
동작: 수정완료를 눌러 저장한다
결과: 종료한 악기가 원생 목록·상세에서 사라지고 정기 일정이 오늘 이후로 취소되며 다른 악기는 그대로다. 정기 외 예정 일정(이동·보강·개인레슨)이 남아 있으면 건수를 안내하고, 이미 만들어진 월 수강료 기록은 바뀌지 않는다는 안내가 확인 창에 있었다.

조건: 수강 중인 악기가 하나뿐인 원생의 수정 폼을 연다
동작: [수강 종료]를 확인한다
결과: 버튼이 비활성이고 "수강 중인 악기는 최소 1개 있어야 합니다. 모두 종료하려면 휴원·퇴원 처리를 해 주세요." 취지의 안내가 보이며, 서버도 같은 이유로 거부한다.

조건: 피아노를 학원레슨과 개인레슨으로 함께 수강하는 원생의 수정 폼을 연다
동작: 학원레슨 수강의 수업 형태 선택지를 본다
결과: 이미 개인레슨으로 수강 중이라 개인레슨은 선택할 수 없고 이유가 보이며, 저장 전에 서버 오류가 나지 않는다.

조건: 바이올린(개인레슨 전용)을 수강하는 원생의 수정 폼을 연다
동작: 수업 형태 선택지를 본다
결과: 학원레슨은 고를 수 없다. 이전 데이터로 학원레슨이 저장된 바이올린은 현재 값이 계속 선택되어 있다.

조건: 다른 사용자가 원생의 담당 선생님을 바꿨고 내 화면은 수정·상태 변경 결과를 이미 표시하고 있다
동작: 목록이 다시 불러와진다
결과: 서버의 새 값이 보이고 내 화면의 이전 합친 값이 남지 않는다. 다시 불러온 결과가 같으면 합친 값이 유지된다.

조건: 악기를 다른 악기로 바꾸고 싶다
동작: 기존 악기의 악기 칸을 본다
결과: 읽기 전용이고 "종료하고 새 악기를 추가"하라는 안내가 있으며, 종료와 추가를 한 번에 저장하면 교체된다.

조건: 종료한 악기와 같은 악기·수업 형태를 다시 추가한다
동작: 저장한다
결과: 새 수강 기록이 따로 생기고 종료한 수강 기록은 그대로 남으며 서버가 중복 오류를 내지 않는다. 종료일 당일이나 그 전 날짜로 다시 시작하려 하면 종료일을 알려 주며 거부한다.

조건: 3월에 시작해 9월에 종료한 악기를 11월에 다시 추가했고 원장이 3~8월 월 수강료를 한 번도 열어 보지 않았다
동작: 3~8월과 11월의 월 수강료를 연다
결과: 종료한 수강 기간의 3~9월 수강료와 새 수강의 11월 이후 수강료가 모두 만들어지고 예전 기간의 수강료가 빠지지 않는다.

조건: 종료한 악기의 월 수강료를 본다
동작: 종료일이 속한 달과 그 다음 달의 월 수강료를 연다
결과: 종료일이 속한 달까지는 만들어지고 그 다음 달부터는 만들어지지 않는다. 이미 만들어진 달의 기록은 그대로다.

조건: 인원·거래처 > 원생에서 데스크톱 폭(약 1000px)으로 목록을 연다
동작: 검색·필터·정렬·초기화 영역을 본다
결과: 모든 컨트롤이 카드 안에 들어오고 밖으로 넘치지 않는다.

조건: 교재 메뉴에서 출고 또는 결제 완료 탭으로 이동한다
동작: 헤더 하위 탭과 사이드바를 본다
결과: 지금 보는 탭만 선택 표시되고 재고 탭은 선택 표시되지 않는다.

조건: 피아노와 바이올린을 함께 배우는 원생의 피아노 담당 선생님만 바꾼다
동작: 수정 후 저장한다
결과: 바이올린의 담당 배정은 바뀌지 않는다.

조건: 담당 선생님이 휴직·퇴사로 선택 목록에 없는 원생을 수정한다
동작: 다른 값을 바꾸고 저장한다
결과: 담당 선생님이 첫 번째 선생님으로 조용히 바뀌지 않고 기존 값이 유지된다.

조건: 같은 이름의 원생이 이미 있다
동작: 등록 폼에 같은 이름을 입력한다
결과: 홍길동a, 홍길동b처럼 구분하라는 경고가 보이지만 저장은 막지 않는다.

조건: 학원 피아노 레슨에서 수강 요일을 2·3·4~5개 고른다
동작: 진도를 선택한다
결과: 가격표의 주 2회·주 3회·주 4·5회 구간 레슨비가 자동으로 정해지고 최종 수강료는 레슨비에서 매달 적용 할인을 뺀 금액이다.

조건: 학원 피아노 레슨에서 수강 요일을 1개 또는 6개 고른다
동작: 레슨비를 확인한다
결과: 자동 계산이 꺼지고 가격표에 없다는 안내와 함께 레슨비를 직접 입력한다.

조건: 두 자녀·두 악기·지인 소개 할인을 복수 선택한다
동작: 저장한다
결과: 두 자녀·두 악기는 매달 −10,000원씩, 지인 소개는 소개한 달의 월 고정 수입 기록에만 −10,000원이 반영된다. 이미 만들어진 달의 기록은 바뀌지 않는다.

조건: 나이 10살로 2026년에 등록한 원생을 2027년에 본다
동작: 목록을 연다
결과: 표시 나이는 11살이고 저장한 초3 학년은 초4로 진급한다. 수동으로 수정한 학년을 나이 입력이 덮어쓰지 않는다.

조건: 미성년 원생의 나이를 입력한다
동작: 등록 폼을 확인한다
결과: 연령에 맞는 초1~고3 학년과 `학생` 직업이 제안되며 둘 다 수정할 수 있다.

조건: 나이 또는 출생연도 중 하나를 입력한다
동작: 다른 칸과 학년 제안을 확인한다
결과: 현재 연도 기준 한국식 나이로 다른 값이 계산되고 1~7세는 `유치원생(미취학아동)`이 제안된다. 한쪽을 비우면 둘 다 비워지고 수동 학년은 덮어쓰지 않는다.

조건: 개인레슨 수강 요일을 1일·2일·3일로 바꾼다
동작: 월 횟수와 요일별 시간을 입력한다
결과: 1일은 월 4회, 2일은 월 8회가 되고 3일 이상은 월 횟수를 직접 입력한다. 40분·60분 수업 길이를 고르고 시작 시간을 입력하면 종료 시간이 자동 계산된다.

조건: 가격표 금액을 직접 수정한 뒤 진도나 요일을 바꾼다
동작: 레슨비와 `가격표로 재계산`을 확인한다
결과: 직접 입력한 금액은 유지되고 재계산 버튼을 눌렀을 때만 현재 가격표 금액으로 바뀐다.

조건: 직접 입력한 레슨비가 있는 피아노 수강의 수업 형태를 학원레슨에서 개인레슨으로 바꾼다
동작: 수업 형태 선택을 확정한다
결과: 이전 직접 입력 금액은 이어 쓰지 않고 개인레슨의 요일별 월 횟수·40분 기본값과 가격표 금액으로 초기화된다.

조건: 원생 상세를 연다
동작: 수강료 요약을 확인한다
결과: 활성 수강 기준 할인 전 월 합계, 매월 할인 합계, 최종 월 수강료가 표시된다.

조건: 원생에게 두 번째 연락처가 저장되어 있다
동작: 수정 폼에서 두 번째 관계와 번호를 모두 비우고 저장한다
결과: 첫 번째 연락처는 유지되고 두 번째 연락처만 삭제된다.

## 원생 목록

조건: 운영자가 원생 목록을 연다  
동작: 현재 학원의 원생 목록을 조회한다  
결과: 현재 학원의 원생만 이름 가나다순으로 표시된다.

조건: 운영자가 원생 목록에서 검색어를 입력한다  
동작: 이름, 담당 선생님, 악기, 정기 요일과 대조한다  
결과: 검색어가 포함된 원생만 표시된다.

조건: 운영자가 원생 목록에서 담당 선생님, 악기, 정기 요일 필터를 선택한다  
동작: 목록을 다시 계산한다  
결과: 선택한 필터 조건을 모두 만족하는 원생만 표시된다.

조건: 운영자가 정렬 기준(이름·담당 선생님·악기·정기 요일)을 바꾼다
동작: 목록을 다시 계산한다
결과: 선택한 기준으로 정렬되고 같은 값이면 id로 고정되어 페이지 경계에서 중복·누락이 없다.

조건: 원생의 정기 요일이 여러 개다
동작: 목록에서 요일을 본다
결과: 요일은 입력 순서와 상관없이 월→일 순서로 표시된다.

조건: 선생님 계정으로 원생 화면을 연다
동작: 목록을 본다
결과: 담당 원생의 이름·악기·정기 요일만 읽기 전용으로 보이고 등록·수정·휴원·퇴원 버튼, 학교·나이·수강료·연락처는 보이지 않는다. 서버(`list_students_for_teacher`)가 이 세 값만 내려주며, 선생님은 수강 정보 표(수강료·할인)를 직접 조회할 수 없다.

## 거래처 등록

조건: 운영자가 거래처를 등록한다  
동작: 거래처명, 연락처, 종류, 비고를 입력하고 저장한다  
결과: 현재 학원 거래처로 등록된다.

조건: 거래처명 또는 종류가 비어 있다  
동작: 거래처를 저장하려 한다  
결과: 저장을 막고 필수 입력 오류를 표시한다.

조건: 등록된 거래처가 있다  
동작: 목록에서 수정을 누르고 거래처명, 연락처, 종류, 비고를 바꿔 저장한다  
결과: 같은 거래처 정보가 갱신되고 목록에 반영된다.

조건: 등록된 거래처가 있고 원장 또는 데스크가 목록을 본다
동작: 삭제를 누르고 확인창에서 삭제를 확인한다
결과: 거래처가 목록에서 사라지고, 교재 발주 내역에는 거래처 이름이 그대로 남는다. 취소하면 아무것도 바뀌지 않고, 실패하면 확인창이 열린 채 안내가 나온다.

## 선생님 등록

조건: 원장이 선생님을 등록한다
동작: 담당 파트(선택 목록), 연락처, 계약 기간, 주민등록번호, 급여 형태를 입력하고 저장한다
결과: 현재 학원 선생님으로 등록된다  
그리고: 등록일은 서울 기준 오늘로 자동 저장되고 폼에서는 수정하지 않는다
그리고: 주민등록번호는 암호화해 저장하고 목록과 상세에는 `900101-1******`처럼 마스킹해 보인다.

조건: 선생님의 계약 시작일과 종료일 중 일부 또는 전부가 비어 있다
동작: 선생님 목록을 확인한다
결과: 계약 기간은 각각 `시작일~`, `~종료일`, `-`로 보이고 둘 다 있으면 `시작일~종료일`로 보인다.

조건: 원장이 비율제 한쪽 몫을 0~10 정수로 입력한다
동작: 값을 입력하거나 화살표로 1단위 변경한다
결과: 반대쪽이 자동으로 `10 - 입력값`이 되어 합계 10을 유지한다. 소수나 범위 밖 값은 이유를 안내하고 저장하지 않는다.

조건: 선생님 근무 요일이 임의 순서로 저장되어 있다
동작: 목록과 상세를 확인한다
결과: 월·화·수·목·금·토·일 순서로 표시된다.

조건: 데스크가 선생님을 등록하거나 수정한다
동작: 폼을 연다
결과: 급여 형태·금액·비율 칸과 목록의 급여 컬럼, 급여 형태 필터가 보이지 않고 기본 정보만 저장된다. 서버도 급여 인자가 오면 원장이 아닌 호출을 거부한다.

조건: 주민등록번호가 13자리가 아니거나 생년월일·성별 자리가 올바르지 않다
동작: 저장하려 한다
결과: 저장을 막고 고쳐야 할 이유를 표시한다(서버도 같은 검증을 한다).

조건: 원장이 선생님 상세에서 `원문 보기`를 누르고 확인한다
동작: 주민등록번호 원문을 요청한다
결과: 원문이 잠시 보이고 열람 기록이 남는다. 숨기기·상세 닫기·수정 전환 시 지워지고 캐시에 남지 않는다. 데스크·선생님은 원문을 볼 수 없다.

조건: 수정 폼을 열 때 선생님 몫이 0%이거나 비율 설정이 없다
동작: 폼 초기값을 본다
결과: 4:6 같은 값으로 채우지 않고 있는 값 그대로(없으면 빈 칸) 보인다.

조건: 선생님명, 담당 파트, 연락처, 주민등록번호 보안 참조 또는 마스킹 값이 비어 있다  
동작: 선생님을 저장하려 한다  
결과: 저장을 막고 필수 입력 오류를 표시한다.

조건: 지원하지 않는 급여 형태를 선택했다  
동작: 선생님을 저장하려 한다  
결과: 저장을 막고 급여 형태 오류를 표시한다.

## 원생 상태 전환

조건: 휴원 원생이 있다  
동작: 재원 처리한다  
결과: 확인 절차를 요구하고 재원 상태로 복구한다.

조건: 휴원 원생이 있다  
동작: 퇴원 처리한다  
결과: 확인 절차를 요구하고 퇴원일을 기록한다.

조건: 퇴원 원생이 있다  
동작: 휴원 처리한다
결과: 확인 절차를 요구하고 휴원 상태로 이동한다(휴원 ↔ 퇴원 전환 모두 허용).

조건: 휴원·퇴원 때 정기 레슨 일정이 닫힌 원생이 있다
동작: 재원 처리한다
결과: 활성 수강 정보의 요일별 시간으로 정기 레슨 시리즈가 복귀일부터 다시 만들어지고 그 달 일정이 생성된다. 복귀일 이전에 취소한 일정은 되살리지 않는다.

조건: 이미 재원인 원생을 다시 재원 처리한다(목록이 낡은 경우)
동작: 상태 변경을 요청한다
결과: 서버가 "이미 해당 상태입니다. 목록을 새로고침해 주세요."로 거부하고 처리 시각과 이력은 바뀌지 않는다. 처리 시각은 서버 시각으로 기록한다.

## 원생 보관 정책

조건: 퇴원 원생의 퇴원일이 기록되어 있다  
동작: 보관 만료일을 계산한다  
결과: 퇴원일로부터 30일 뒤 삭제 가능일과 남은 일수를 표시한다.

조건: 퇴원 원생의 30일 보관 기간이 지났다  
동작: 매일 새벽 자동 보관 작업(`archive_expired_people`, pg_cron)이 실행된다
결과: 원생 데이터는 지우지 않고 `archived_at`만 기록해 목록에서 사라진다. 실제 삭제와 복구 화면은 별도 정책 결정 전까지 제공하지 않는다. 이 함수는 앱 사용자가 직접 실행할 수 없다.

조건: 퇴원 원생 또는 퇴사 선생님의 상태 화면 상세를 연다
동작: 삭제하려 한다
결과: 비활성 삭제 버튼과 "결제·회차권·급여 기록을 보존하기 위해 삭제할 수 없습니다. 보관 상태로 유지됩니다." 안내가 보인다.

결과: 교재 가격이 새 가격으로 바뀌고 폼에 미리 안내한다. 이미 만든 출고 건의 가격은 바뀌지 않는다.

결과: 재고 수량은 1개가 된다
그리고: 해당 판매는 결제 대기 상태가 되어 출고목록에 표시된다.

조건: 교재 재고 수량이 2개다
동작: 수량 3권으로 출고하려 한다
결과: 출고를 막고 "재고가 부족합니다. 남은 재고는 2권입니다."를 표시한다.

조건: 교재 재고 수량이 1개다

결과: 재고 수량은 0개가 된다

결과: 교재 가격이 자동 입력되고 출고하는 자리에서 고칠 수 있다. 고친 가격(단가)이 그 출고 건에 저장되고 교재 가격은 바뀌지 않는다.

동작: 출고 등록한다
결과: 한 건의 금액은 45,000원이다.

조건: 출고 선택지의 원생을 연다
동작: 원생을 고른다
결과: 재원 원생만 나온다.

조건: 다른 학원의 재고가 있다

결과: 출고를 막고 학원 범위 오류를 표시한다.

결과: 학원 고정 수입이 기본으로 열리고 탭은 학원 고정 수입, 입출입내역, 교재 내역, 선생님 월급, 전체 수입 순서다.

조건: 원장이 지난달을 보다가 다른 탭으로 옮긴다
동작: 조회 월을 확인한다
결과: 같은 달이 유지되고 이번 달보다 뒤의 달은 고를 수 없다.

조건: 미입금 또는 미납 상태의 수강료 항목이 있다
동작: 입금일을 입력하고 입금 처리한다
결과: 상태는 입금 완료가 되고 입출입내역에 수입이 같은 시점에 기록된다
그리고: 입금일이 보고 있는 월 밖이면 어느 월 내역으로 기록되는지 안내한다.

조건: 미입금 상태의 수강료 항목이 있다
동작: 미납 버튼을 누른다  
결과: 상태는 미납이 되고 미납 인원 목록에 나타난다
그리고: 이후 입금 처리하면 미납 인원 목록에서 자동으로 빠진다.

조건: 아직 처리하지 않은 미입금 원생이 있다
동작: 미납 인원 목록을 연다
결과: 미납을 누른 원생만 보이고 미입금 원생은 보이지 않는다.

조건: 입금 완료된 수강료 항목이 있다
동작: 입금 취소를 확인한다
결과: 연결된 입출입내역이 삭제되고 미입금으로 돌아간다
그리고: 확인 안내에 입출입내역이 삭제된다는 사실이 쓰여 있다.

조건: 결제 금액이 0원인 수강료 항목이 있다
동작: 입금 처리를 하려 한다
결과: 버튼은 비활성이고 0원이어서 입금할 수 없다는 이유가 보인다.

조건: 입금 완료인데 입출입내역 행이 지워진 항목이 있다
동작: 목록을 본다
결과: "원장 기록 없음"으로 표시된다.

## 입출입내역

조건: 원장이 월을 선택한다
동작: 입출입내역을 연다
결과: 월별 총 수입(입금)과 월별 총 출금 카드가 보이고 검색·필터와 무관하게 그 월 전체 합계다.

조건: 원장이 수동 수입 또는 지출을 입력한다
동작: 날짜(기본 오늘), 유형, 분류, 내용, 금액을 저장한다
결과: 수동 ledger 항목이 생성된다
그리고: 수입 유형이면 수입 분류만, 지출 유형이면 지출 분류만 고를 수 있다.

조건: 자동으로 기록된 입출입내역이 있다
동작: 수정 폼을 연다
결과: 유형과 출처는 바꿀 수 없고 금액·날짜·설명·분류만 수정할 수 있으며 원천에는 반영되지 않는다는 안내가 보인다.

조건: 권한 없는 사용자가 수동 수입 또는 지출을 입력한다  
동작: 저장하려 한다  
결과: 수동 입력이 거부된다.

조건: 저장 버튼을 빠르게 두 번 누른다
동작: 처리 중에 다시 누른다
결과: 한 건만 저장된다.

## 교재 내역

조건: 거래처에 기존 교재와 새 도서를 함께 발주했다
동작: 발주·입고 탭에서 발주일·품목별 수량·매입가를 저장하고 입고일과 새 도서 판매가를 확인한다
결과: 입고는 한 번만 확정되고, 기존 교재 수량이 증가하며 새 도서는 판매가와 함께 재고에 추가된다.

조건: 입고한 발주의 교재를 이미 출고했다
동작: 발주 취소를 확인한다
결과: 판매된 재고를 되돌리지 않고 취소 불가 이유를 알려 준다.

조건: 원장이 입고 전 발주 대금을 지급한다
동작: 지급일을 선택해 확정한다
결과: 지급 상태와 `교재발주` 출처의 지출 원장 행이 함께 생긴다. 같은 요청을 다시 보내면 중복 지출을 막는다.

조건: 같은 원생에게 같은 날 여러 교재를 출고했다
동작: 수입 관리의 교재 내역을 연다
결과: 판매는 한 행으로 묶이고 펼치면 품목별 금액과 입금일을 확인한다. 월 수입·발주 지급·차액은 원장의 실제 입출금일 기준이다.

조건: 결제 대기와 결제 완료 교재 출고가 섞여 있다
동작: 교재 내역 탭을 연다
결과: 결제 완료 건만 입금일이 속한 월 기준으로 이름·도서명·가격·수량·금액·출고일·입금일과 "교재 수입 총합"(금액의 합)이 보인다.

조건: 결제 대기 교재 출고가 있다
동작: 원장과 데스크가 출고 목록을 본다
결과: 둘 다 나중 결제 완료 버튼이 보이지 않는다. 등록 시 결제 완료를 선택하는 권한은 원장에게만 있다.

## 전체 수입 그래프

조건: 운영자가 특정 연도의 전체 수입을 본다
동작: 현재 학원의 ledger를 집계한다  
결과: 연간 수입·지출·순수익 합계와 월별 수입·지출·순수익이 표시되고 분류별 수입에는 지출이 섞이지 않는다.

조건: 운영자가 그래프 지표를 고른다
동작: 악기 전체, 악기별, 학원 수입, 지출 중 하나를 선택한다
결과: 선택한 연도의 1~12월 금액이 세로 막대와 수치 라벨, 대체 표로 표시된다
그리고: 악기별은 악기를 하나 고르며 수납 완료된 월수강료만 집계한다.

조건: 선택한 월에 입금 완료·미입금·미납 원생이 섞여 있다
동작: 전체 수입 탭을 연다
결과: 상태별 인원과 금액, 미납 인원 목록이 보인다.

## 급여 지급

조건: 비율제 선생님이 이번 달 140,000원 수강료의 원생을 4회 모두 등원 확인했고 선생님 비율이 60%다
동작: 급여를 계산한다  
결과: 기본 급여 84,000원, 원천징수 2,772원, 세후 81,228원이다.

조건: 같은 원생의 그 달 정규 예정 수업 4회 중 2회만 등원 확인했다
동작: 비율제 급여를 계산한다
결과: 1회 레슨비(수강료 ÷ 예정 4회)에 등원 2회만 곱해 월 전액이 아닌 일부만 계산된다.

조건: 비율제 선생님이 개인레슨을 등원 확인했다
동작: 급여를 계산한다
결과: 1회 레슨비는 회차권 결제 금액 ÷ 부여 회수이며 학원 레슨과 원생별로 계산해 합산한다
그리고: 결제 금액을 알 수 없는 개인레슨은 계산에서 제외하고 그 건수를 안내한다.

조건: 시급제 선생님의 출근 요일·시간이 설정되어 있다
동작: 급여를 계산한다
결과: `시급 × 그 달 출근 일정의 근무 시간 합계`(계약 시작·종료일이 있으면 그 안의 날짜만, 없으면 그 달 전체)에서 3.3% 원천징수를 반영하고 근거로 `근무 N시간 (출근 일정 기준)`을 보인다. 등원 확인 수업과는 무관하다.

조건: 시급제 선생님의 출근 일정이 비어 있거나 요일은 있는데 시간이 비어 있다
동작: 급여를 계산한다
결과: 지급할 수 없고 "출근 시간을 설정해 주세요…" 같은 안내가 나온다.

조건: 월급제 선생님이 등록되어 있다  
동작: 월 급여를 계산한다  
결과: 월 고정 급여에서 3.3% 원천징수를 반영한 세후 급여가 계산된다.

조건: 원천징수 원 단위 처리 정책이 미확정이다
동작: 급여를 계산한다
결과: 정책 상수(현재 내림)로 원천징수액을 계산한다.

조건: 한국 시간 새벽에 있었던 수업이 UTC 기준으로 전날이다
동작: 월별 급여를 계산한다
결과: 한국 시간 날짜의 월에 포함된다.

조건: 급여 설정이 비어 있는 선생님이 있다
동작: 선생님 월급 탭을 연다
결과: 화면은 깨지지 않고 해당 선생님은 "설정 확인 필요"로 표시되며 지급 버튼이 없다.

조건: 지급할 금액이 0원이다
동작: 지급 확정을 하려 한다
결과: 버튼은 비활성이고 지급할 금액이 없다는 이유가 보인다.

조건: 급여 지급이 확정된다
동작: 지급일을 입력하고 지급 확정한다
결과: 입출입내역에 지출 항목이 같은 시점에 생성된다.

조건: 같은 선생님의 같은 달 급여가 이미 지급 완료됐다(급여 형태가 바뀐 경우 포함)
동작: 다시 지급 확정한다
결과: 중복 지급이 막힌다.

조건: 지급 확정 버튼을 거의 동시에 두 번 누른다
동작: 두 요청이 서버에 도착한다
결과: 지출은 한 건만 기록된다.

조건: 지급 완료된 급여가 있다
동작: 원장이 지급 취소를 확인한다
결과: 연결된 지출 행이 삭제되고 미지급으로 돌아간다.

조건: 지급 완료 후 그 달 등원 기록이 바뀌었다
동작: 선생님 월급 탭을 연다
결과: 지급액은 그대로이고 "지급 후 등원 기록이 변경되었습니다" 경고가 보인다.

조건: 지급 확정을 누르는 사이 다른 화면에서 그 선생님의 등원 기록이 바뀌어 금액이 달라졌다
동작: 지급일을 입력하고 확인한다
결과: 지급하지 않고 "등원 기록이 바뀌어 금액이 달라졌습니다. 새 금액을 확인한 뒤 다시 확정해 주세요."를 알린다.

조건: 서버가 확정할 때 보낸 등원 수업 목록이 그 선생님·그 달의 실제 등원 수업 전체와 다르다
동작: 급여 지급을 요청한다
결과: 서버가 한국어 오류로 거부하고 지출은 기록되지 않는다.

조건: 시급제 선생님의 출근 일정이 35분씩 5번이다
동작: 급여를 계산한다
결과: 날짜마다 내리지 않고 총 175분으로 한 번에 `floor(시급 × 분 ÷ 60)`을 계산하며 서버와 같은 값이 나온다.

조건: 같은 원생·악기를 두 선생님이 한 달에 나눠 가르쳤다
동작: 두 선생님의 비율제 급여를 계산한다
결과: 월 수강료는 원생·악기 단위의 예정 수업 수로 한 번만 나뉘어 두 선생님 급여의 합이 월 수강료를 넘지 않는다.

조건: 수동·특별 수업이 있다
동작: 학원 레슨의 1회 레슨비를 계산한다
결과: 분모(예정 수업 수)는 정규·이동 수업만 세고, 수동·특별 수업의 등원은 등원 횟수에는 포함한다.

조건: 그 달 월 수강료 snapshot 금액과 현재 수강료가 다르다
동작: 급여를 계산한다
결과: 그 달 snapshot 금액을 쓴다.

조건: 지난달에 퇴사한 선생님이 8월에 등원 확인된 수업이 있거나 정산 기록이 있다
동작: 8월 선생님 월급을 연다
결과: 퇴사 선생님도 그 행이 보인다. 기록이 없는 퇴사자와 입사 전 달의 재직 선생님은 행이 없다.

조건: 데스크 직원이 수입 관리 화면을 열려 한다
동작: 어떤 설정이든 접근한다
결과: 접근할 수 없다(수입 관리는 원장 전용).

조건: 입금 완료된 교재의 입출입내역 행이 지워졌다
동작: 교재 내역을 연다
결과: 해당 건에 "원장 기록 없음"이 표시된다.

조건: 거래 내역이 한 달에 1000건을 넘는다
동작: 입출입내역이나 급여를 연다
결과: 서버가 1000건씩 끝까지 읽어 합계·급여가 잘리지 않고, 비정상적으로 많으면 조용히 자르지 않고 기간을 좁히라고 알린다.

조건: 미납 상태인 항목에서 미납 해제를 누르는 사이 다른 화면에서 입금 처리됐다
동작: 미납 해제를 요청한다
결과: 서버가 미납 상태일 때만 처리하므로 거부되고 입금 기록은 그대로다.

조건: 선생님을 등록하면서 계약 시작일·종료일을 비워 둔다(한쪽만 입력해도 된다)
동작: 선생님을 저장하고 상세를 연다
결과: 저장된다. 상세의 계약기간은 `계약기간 없음`(한쪽만 있으면 `2026-09-01부터`·`2027-08-31까지`)으로 보이고, 둘 다 입력했는데 종료일이 시작일보다 빠르면 저장하지 못한다. 시급제 급여는 계약기간이 없으면 그 달 전체를 기준으로 계산한다.

조건: 교재 등록 폼에 구입 거래처명(선택)을 입력해 등록한다
동작: 재고 표를 연다
결과: "구입 거래처" 열에 입력한 이름이 보이고, 입력하지 않은 교재는 `-`로 보인다.

조건: 구입 거래처가 있는 교재와 같은 도서명으로 재입고한다

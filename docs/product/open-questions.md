## 2026-10-15 spec-review에서 추가된 질문

임시 결정은 사용자가 정한 것이며 최종 정책 확정 전까지 유지한다.

- **삭제 방식(임시 결정)**: 퇴원 원생·퇴사 선생님의 삭제 버튼은 비활성이고 보관만 허용한다. 2026-10-16 운영 DB에 적용한 회차권 이력 migration은 기존 삭제 RPC 실행 권한도 회수했다. 정식 정책(hard/soft delete, 연쇄 범위, 30일 후 자동 처리, 복구 UI)을 정해야 한다. 거래처·회차권·교재 출고·개인레슨·학원 일정의 삭제 허용 여부와 사유 입력도 함께 정한다.
- **잔여 0 출석**: 회차권 잔여가 0인 원생이 실제로 등원했을 때 출석을 막을지(현재), 기록은 허용하고 마이너스/미정산으로 표시할지.
- ~~**만료 기준일과 재등록 공백**~~ → 해결(2026-10-16): 수업 날짜를 기준으로 각 등록 이력의 유효 구간을 검사하며, 재등록 전 공백 날짜에는 사용하지 못한다. 잔액 행은 원생·악기별 한 행으로 병합한다.
- **차감 정정**: 출석을 결석으로 정정하면 회차가 사유 없이 자동 복구되고 이력이 남지 않는다. 사유 입력, 이력 보관(복구 취소 표시), audit 기록이 필요한지.
- **미래 날짜 출석**: 미래 수업에 출석 처리를 허용할지, 과거 수업은 며칠까지 허용할지.
- ~~**0원 회차권**~~ → 해결: 결제 금액은 선택 입력이며 0 또는 빈 값을 허용한다(입력했을 때만 수입 내역에 기록).
- ~~**재등록 이력**~~ → 해결(2026-10-16): 한 잔액 행에 병합하되 등록일·회수·유효기간·당시 결제 금액·연결 원장은 구매 건별로 보존한다. 복원할 수 없는 과거 병합 기록이 있으면 migration을 중단한다.

- **휴원/퇴원 시 개인레슨**: 원생이 휴원·퇴원하면 예정된 개인레슨을 자동 취소할지(현재 정기 학원 일정만 취소).
- **개인레슨 수정·취소**: 이동·취소·삭제를 허용할지, 출석 이후 취소하면 회차를 복구할지 막을지. 시간 충돌을 막을지 경고만 할지, 같은 원생·선생님의 학원 수업과의 겹침도 대상인지.
- ~~**자동 생성 원장 행**~~ → 해결(2026-10-16): 수정·삭제를 허용하고 audit을 남긴다. 회차권 월수입은 연결 원장의 현재 금액·발생일을 따른다.
- **교재 재고·결제 완료**: 교재 등록·재고·입고일·자동 가격·출고 시 재고 부족 허용 여부, 결제 대기 건을 결제 완료로 바꾸는 권한과 화면.
- **미수금 범위**: 미수금 현황에 수강료 미납만 넣을지, 교재 결제 대기와 회차권 결제까지 포함할지.
- **teacher·desk 권한 반영**: `allowDeskFinance` 플래그를 실제로 연결할지, teacher의 학원 출석·개인레슨 등록·본인 급여(`/my/payroll` 화면)를 허용할지. 회차권 데스크 수정과 담당 악기 제한 조회는 확정했다. 현재 teacher의 "내 급여" 링크는 화면이 없어 숨겼다.
- **원생 수정 폼 범위**: 등록 폼과 같은 필드(등록일, 나이, 학년, 학교, 직업, 연락처, 복수 악기, 요일별 시간, 할인 구분)를 수정할 수 있게 할지. 수정 RPC(스키마) 변경이 필요하다.
- **페이지네이션 방식**: 지금은 전체를 한 번 조회해 브라우저에서 자른다. 데이터가 커지면 서버 페이지네이션이 필요하고, 그때 DB collation이 한글 가나다순을 보장하는지 확인해야 한다.
- **오류 문구 위치**: 영문 RPC 예외를 DB 메시지에서 한글화할지, 지금처럼 클라이언트에서 변환할지.
- **데모 계정**: `owner@lesson.local` 계정이 원격 DB에 남아 있는지 확인하고 운영 DB라면 제거한다(로그인 폼 기본값은 이미 제거).
- **급여 대상 범위**: 선생님 월급 화면은 재직 선생님만 계산한다. 이번 달 중 퇴사·휴직한 선생님의 미지급 급여 행, 지난달 지급 이력을 계속 보여줄지 정해야 한다.
- ~~**삭제 RPC 회수**~~ → 해결(2026-10-16): `delete_withdrawn_student`·`delete_resigned_teacher`의 `authenticated` 실행 권한을 운영 DB에서 회수했다. 정식 삭제 정책은 위 질문으로 남긴다.
- **대량 데이터 한도**: 목록·급여 원천(`lesson_events`)·원장(`ledger_entries`)은 범위·페이지 조건 없는 단일 조회라 서버 `max_rows`(로컬 1000)에서 조용히 잘릴 수 있다. 원격 설정을 확인하고 금액 집계는 월 범위 조회·서버 집계로 옮길지 정한다.
- **급여 지급 금액 재계산**: 지급 확정은 브라우저가 계산한 금액을 RPC로 보낸다. 서버에서 재계산·대조할지 정한다(스키마 영향).

## 2026-10-15 레슨시간표 명세 반영(2회차)에서 추가된 가정과 질문

### 사용자 결정(확정)

- DB 변경은 migration 파일과 SQL 문자열 계약 테스트까지만 작성했고 원격에는 적용하지 않았다(`supabase/migrations/20261016090000_*`, `20261016090100_*`).
- 개인레슨 길이는 원생의 요일별 `종료−시작`에서 유도하고 없으면 30분이다.
- 담당 선생님은 `teachers.part`가 악기와 같은 재직 선생님으로 거르고, 해당자가 없으면 전체 재직 선생님과 안내를 보여준다.
- 월별 포스트잇은 새로 추가하고 날짜별 메모는 유지한다.
- 학원 출결은 확인/취소 일괄 저장과 결석확인→사유서→최종확인 흐름이며 마감 후에도 초기화로 수정한다.
- 선생님은 UI만 정리한다(학원 쓰기 버튼 숨김, 개인레슨 등록 불가).
- 회차권은 명세대로 하되 결제 금액은 선택 입력이다.
- 드래그 이동은 같은 달·데스크톱, 탭 구조와 primary 색은 유지한다.

### 임시 가정(이견이 있으면 알려 주세요)

1. 보강은 보강일에 `[보강 수업]` 일정을 새로 만들고 원본은 결석 기록으로 남긴다.
2. 일정 삭제는 사유 필수이며 `status='deleted'`로 숨기고 결석인원에 기록하지 않는다. 출결이 처리된 일정은 삭제할 수 없다.
3. 요일별 인원확인은 선택한 달의 정규 일정 기준 월~금 요일별 고유 원생이다.
4. 보강일 추천은 14일·월~금·정규 요일 제외·인원 적은 순·상위 5개이며 다음 달 날짜의 인원은 추가 조회한다.
5. 보강 시간을 비우면 원본 시간으로 저장하되 `lesson_events.time_unspecified`로 표시를 숨긴다.
6. 사유서 자동 기록 형식은 보강 `원생명, 8/14 [금요일] 15:00 보강 - 8/12 [수요일] 사유`, 패스 `원생명, 8/12 [수요일] 사유없음`이다.
7. 개인레슨 날짜 클릭은 출석 확인을 유지하고 그 안에서 등록창을 연다. 충돌은 같은 선생님의 개인레슨만 검사한다.
8. 개인레슨 "등원 확인 취소"는 출결을 지우고 회차를 복구해 예정 상태로 되돌린다. 기존 "결석" 버튼은 유지한다.
9. 회차 `현재/총`에서 총은 유효 회차권의 총 부여 회수, 현재는 조회한 달 안의 순번이다.
10. 복사 버튼은 녹색으로 해당 버튼에만 색을 지정한다.
11. 회차권 직접 수정은 부여 회수·잔여 회수·만료일, 사유 필수, 삭제는 제공하지 않는다.
12. 월별 포스트잇은 개인레슨 화면에도 있으며 자동 기록은 학원 레슨표만 한다. 위치·크기는 클라이언트 상태다.

- **선생님↔악기 관계**: 지금은 `teachers.part` 문자열 비교다. 전용 관계 테이블을 둘지 정해야 한다.
- **레슨 길이 컬럼**: 개인레슨 길이를 원생 요일 시간에서 유도하는 대신 전용 컬럼으로 둘지 정해야 한다.
- **충돌 DB 방어**: 개인레슨 시간 충돌은 UI 경고와 서버 검사만 있고 DB 제약(exclusion)은 없다. 같은 원생·선생님의 학원 수업과의 겹침도 대상인지 정해야 한다.
- **개인레슨 취소·삭제·시간 변경**: 이번 명세에 없어 제공하지 않았다.
- **회차권 삭제**: 정책 확정 전까지 제공하지 않는다.
- **`현재/총`의 월 경계**: 월을 넘는 순번(예: 7월 마지막 회차가 전체 몇 번째인지)은 반영하지 않았다.
- **보강 재배정**: 확정한 보강을 되돌리거나 다른 날로 옮기는 UI는 없다.
- **포스트잇 위치 저장**: 위치·크기를 계정·기기에 저장할지(현재는 새로고침 시 기본값).

### 독립 리뷰에서 나온 정책·스키마 질문 (미반영)

- ~~**보강 일정 삭제·이동**~~ → 해결(사용자 결정): 삭제하면 그 결석은 보강 없는 패스로 처리하고, 이동하면 결석 연결을 새 일정으로 옮긴다. 삭제 후 패스를 다시 보강으로 바꾸는 UI는 없다(필요하면 질문).
- ~~**처리된 결석의 서버 보호**~~ → 해결(사용자 결정): `attendance_records` trigger가 처리된 결석의 상태 변경·삭제를 거부한다. 남은 질문: 화면이 새로 조회한 결과를 무시하는 `academySheetsOverride` 동작 점검(오래된 화면이 거부 오류를 받은 뒤에도 갱신되지 않을 수 있음).
- **포스트잇 동시 편집**: 서버가 사유서 한 줄을 이어 붙이는 동안 화면은 전체 내용을 덮어쓰며 편집 중 초안이 새로 조회되면 사라질 수 있다. 낙관적 잠금(`updated_at` 비교)이나 이어붙이기 RPC를 도입할지 정해야 한다.
- ~~**`현재/총` 기준**~~ → 해결(사용자 결정): 달이 바뀌어도 이어서 센다(회차권 유효 시작일 이후, 조회한 달 이전의 취소되지 않은 레슨 수 + 이번 달 순번). 남은 질문: 결석 레슨을 순번에서 뺄지(현재 포함), 회차권이 여러 개로 갱신될 때 시작점(가장 이른 유효 시작일 사용).
- **레슨 길이 원천**: `student_instruments.start_time/end_time`이 이후 요일별 시간표 테이블 도입 후에도 최신인지 확인이 필요하다.

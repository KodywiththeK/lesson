# 교재 관리 기능명세서

- 작성일: 2026-10-17
- 메뉴: 교재 (재고 / 출고 / 결제 완료 / 발주·입고)
- 상태: 개발 요청용 (사용자 결정 반영본, 남은 확인 사항은 11장)
- 근거: 사용자 초안(텍스트 + 와이어프레임 2장), 현재 구현 조사, 사용자 질문 답변 4회(16건)
- 관련 문서: 학원 수입 관리 기능명세서(교재 내역, 입출입내역), 원생·선생님·거래처 관리 기능명세서(원생 삭제·상태)

표기 규칙
- **[확정]** 사용자가 직접 정한 내용
- **[가정]** 사용자가 정하지 않아 계획 단계에서 임시로 정한 내용. 11장에서 확인한다.
- 화면 문구는 사용자에게 보이는 그대로 적었다.

## 1. 개요

### 1.1 목적

교재의 입고(재고)와 원생 판매(출고 → 입금 확인)를 관리하고, 입금이 확인된 판매는 학원 수입 관리의 입출입내역과 교재 내역에 자동으로 기록한다.

### 1.2 메뉴 구성 [확정]

메뉴 "교재" 아래 하위 메뉴 4개를 둔다. 수입 관리와 같은 방식(헤더 하위 탭)이다.

| 탭 | 주소 | 한 줄 설명 | 와이어프레임 영역 |
| --- | --- | --- | --- |
| 재고 | `/books` | 교재 등록·수정·삭제와 재고 확인 | 교재 등록 관리, 교재 재고 상태 |
| 출고 | `/books/shipments` | 원생에게 교재 출고 등록, 입금 전 출고 목록(대기) 관리 | 도서 구매 목록, 출고목록 |
| 결제 완료 | `/books/paid` | 입금이 확인된 판매 기록 | 결제완료(와이어프레임 표기 "결재완료"는 "결제 완료"로 통일) |
| 발주·입고 | `/books/orders` | 거래처 발주, 전량 입고, 지급·취소 기록 | 2026-10-20 운영 개선 |

### 1.3 접근 권한

| 동작 | 원장 | 데스크 | 선생님 |
| --- | --- | --- | --- |
| 메뉴·화면 열기 | 가능 | 가능 | 접근 불가(메뉴 숨김, 직접 주소는 안내 화면) |
| 교재 등록·수정·삭제(보관), 재고 수정 | 가능 | 가능 | 불가 |
| 출고 등록·수정·삭제(결제 완료 전) | 가능 | 가능 | 불가 |
| 출고 등록에서 바로 결제 완료 선택 | 가능 | 불가(선택지가 보이지 않음) | 불가 |
| 출고 후 결제 대기 → 결제 완료 | 불가(출고 등록 시에만 가능) | 불가 | 불가 |
| 결제 취소(결제 완료 → 대기) | 가능 | 불가 | 불가 |
| 결제 완료 목록 보기 | 가능 | 가능(읽기 전용) | 불가 |
| 발주 등록·수정·입고·취소 | 가능 | 가능(지급된 발주의 취소 제외) | 불가 |
| 발주 지급·지급 취소 | 가능 | 불가 | 불가 |

- [확정] 데스크는 교재·재고·출고 관리, 원장은 결제 처리와 결제 취소를 맡는다.
- 화면의 버튼 숨김과 안내 화면은 편의일 뿐이고, 실제 권한은 서버(RPC와 RLS)가 검사한다. 교재·출고 테이블은 브라우저에서 직접 쓰지 못하고 RPC로만 바꾼다.

## 2. 흐름과 상태

```text
교재 등록(입고) → 재고 → 출고 등록 ─┬→ 결제 대기
                                  └→ 결제 완료(원장이 등록 시 입금 확인)
결제 완료 → 결제 취소 → 결제 대기 → 출고 삭제 → 새 출고 등록
```

### 2.1 교재 상태

| 상태 | 뜻 | 재고 표시 |
| --- | --- | --- |
| 재고 있음 | 권수 1 이상 | 권수 |
| 재고 없음 | 권수 0. **목록에서 사라지지 않는다**(학원 특성상 교재가 자주 바뀌지 않으므로 기록이 남아야 함) [확정] | 권수 `0` + "재고 없음" 배지 |
| 삭제(보관) | 재고 목록에서 삭제한 교재. 목록·출고 선택지에서 보이지 않고, 과거 판매 기록은 도서명·가격 스냅샷으로 그대로 남는다 [확정] | 보이지 않음 |

### 2.2 출고 상태

| 상태 | 뜻 | 수정·삭제 |
| --- | --- | --- |
| 결제 대기 | 출고는 됐으나 입금 전 | 가능(원장·데스크) |
| 결제 완료 | 입금일을 입력해 확인한 판매. 입출입내역에 수입이 기록된다 | **수정·삭제 불가**. 원장만 "결제 취소" 가능 [확정] |

### 2.2.1 상태 전이

| 동작 | 이전 상태 | 이후 상태 | 재고 | 입출입내역 | 역할 |
| --- | --- | --- | --- | --- | --- |
| 출고 등록 | (없음) | 결제 대기 | −수량 | 변화 없음 | 원장·데스크 |
| 출고 등록 + 바로 결제 완료(지름길) | (없음) | 결제 완료 | −수량 | 수입 행 생성(입금일 기준) | 원장 |
| 출고 수정 | 결제 대기 | 결제 대기 | 도서·수량이 바뀌면 이전 +, 새 − | 변화 없음 | 원장·데스크 |
| 출고 삭제 | 결제 대기 | (삭제) | +수량 | 변화 없음 | 원장·데스크 |
| 결제 취소 | 결제 완료 | 결제 대기 | 변화 없음(이미 나간 책) | 연결된 수입 행 삭제 | 원장 |

## 3. 재고 탭 (`/books`)

### 3.1 화면 구성 [확정: 와이어프레임]

1. 제목 "교재 등록 관리", 설명 "새로운 교재를 입고 및 등록합니다.", 오른쪽에 **[교재 등록]** 버튼.
2. 제목 "교재 재고 상태", 오른쪽에 "도서명 필터 검색…" 입력과 **오름차순/내림차순 정렬** 토글.
3. 표 컬럼: 도서명 · 가격 · 권수 · 입고일 · 구입 거래처(비어 있으면 `-`) · 관리(수정, 삭제). 비어 있으면 "재고 도서가 없습니다."
4. 표는 공통 표 규칙(데스크톱 표, 태블릿 행, 모바일 카드)을 따르고 폭별로 같은 데이터와 버튼을 제공한다. 하단에 총 건수·페이지 이동·페이지당 10·20·30을 항상 보인다.

기본 정렬은 도서명 가나다 오름차순이고 같은 이름이면 id로 고정한다. 토글은 도서명 방향만 바꾼다.

### 3.2 교재 등록 다이얼로그 [확정: 와이어프레임]

| 항목 | 규칙 |
| --- | --- |
| 도서명 | 필수, 1~100자 [가정]. 입력 칸 안내 "도서명 입력" |
| 가격(원) | 필수, 1원 단위 정수 1~9,999,999 [가정]. 기본값 비움 |
| 권수 | 필수, 정수 0~9,999 [가정]. 기본값 비움 |
| 입고일 | 필수, 기본값 오늘, 오늘 이후(미래)는 선택 불가 [가정] |
| 구입 거래처명 (선택) | 자유 텍스트 0~100자 [확정 2026-10-22]. vendors와 연결하지 않아 거래처를 삭제해도 남는다 |
| 버튼 | [취소] [등록] |

저장하면 재고 목록에 한 줄이 생긴다. 저장 직후 목록과 출고 선택지에 반영된다.

### 3.3 같은 도서명 재입고 [확정]

- 도서명이 이미 등록된 교재와 같으면(앞뒤 공백 제거, 연속 공백 1칸, 대소문자 무시 [가정]) 새 줄을 만들지 않고 **기존 교재의 권수에 입력한 권수를 더한다.**
- 입고일은 입력한 입고일로 바뀐다(최근 입고일) [확정]. 이전 입고 날짜는 남기지 않는다.
- 구입 거래처명은 입력하면 덮어쓰고, 비우면 기존 값을 유지한다 [확정 2026-10-22].
- 입력한 가격이 기존 가격과 다르면 교재 가격을 새 가격으로 바꾼다 [가정]. 폼에 "이미 등록된 교재입니다. 권수가 합산되고 가격이 N원으로 바뀝니다."처럼 미리 안내한다. 이미 만든 출고 건의 가격은 바뀌지 않는다.
- 삭제(보관)한 교재와 같은 도서명은 중복으로 보지 않고 새 교재로 등록한다.

### 3.4 수정

- 수정 다이얼로그는 등록과 같은 필드(도서명, 가격, 권수, 입고일, 구입 거래처명)를 바꾼다. 수정에서는 구입 거래처명을 비우면 값이 지워진다. 권수는 **현재 재고**이므로 직접 고칠 수 있다(0 미만 불가).
- 도서명을 다른 교재와 같게 바꾸면 "이미 등록된 도서명입니다. 같은 이름의 교재의 권수를 수정해 주세요."로 막는다.
- 가격을 바꿔도 이미 출고된 건(대기 포함)의 가격은 바뀌지 않는다. 폼에 "이미 출고된 건에는 반영되지 않습니다." 안내를 보인다 [가정].

### 3.5 삭제(보관) [확정]

- 삭제는 확인 창을 거친다. 확인하면 교재가 재고 목록과 출고 선택지에서 사라진다(보관). 판매 기록은 그대로다.
- 그 교재의 대기 중인 출고가 있으면 확인 창에 "대기 중인 출고 N건이 있습니다. 삭제해도 대기 건은 계속 결제 처리할 수 있습니다."를 함께 보인다 [가정]. 대기 건은 삭제된 교재로 다른 교재를 고르는 수정만 막힌다(6.3).
- 재고가 남아 있어도 삭제할 수 있다.

## 4. 출고 탭 (`/books/shipments`)

### 4.1 도서 구매(출고 등록) 폼 [확정: 와이어프레임 + 수량 칸]

한 줄 폼: 이름(원생) · 도서명 · 가격(원) · **수량** · 출고일 · **[출고 등록]**.

| 항목 | 규칙 |
| --- | --- |
| 이름(원생) | 필수. 선택 안내 "원생을 선택하세요". **재원 원생만** 목록에 나온다 [확정] |
| 도서명 | 필수. 선택 안내 "도서를 선택하세요". 삭제(보관)하지 않은 교재만 나오고 각 항목에 남은 재고가 보인다 |
| 가격(원) | 도서명을 고르면 교재 가격이 **자동 입력**되고, 출고하는 자리에서 **수정할 수 있다** [확정]. 이 가격이 판매 기록의 단가로 저장된다. 정수 1~9,999,999 |
| 수량 | 필수, 기본값 1, 정수 1~999 [가정]. 남은 재고보다 클 수 없다 |
| 출고일 | 기본값 오늘, 오늘 이후(미래)는 선택 불가 [가정] |
| 원장 전용 추가 항목 | 결제 상태 선택(결제 대기 기본, "결제 완료" 선택 가능). 결제 완료를 고르면 **입금일 칸**이 나타나고 기본값은 출고일 [확정] |

- [출고 등록]을 누르면 재고가 수량만큼 줄고, 결제 대기를 골랐으면 출고목록에, 원장이 결제 완료를 골랐으면 결제 완료 목록에 한 건이 생긴다. 한 건의 금액은 **단가 × 수량**이다 [확정].
- 같은 원생에게 서로 다른 교재를 사 주려면 출고 등록을 여러 번 한다.
- 재고가 부족하면 등록하지 않는다: "재고가 부족합니다. 남은 재고는 N권입니다." (재고 0권이면 "재고가 없습니다. 교재를 입고한 뒤 출고해 주세요.") [확정]
- 처리 중에는 버튼을 막아 중복 등록을 막는다.

### 4.2 출고목록(결제 대기) [확정: 와이어프레임]

- 제목 "출고목록". 결제 대기 출고를 확인하고 수정·삭제한다.
- 컬럼: 이름 · 도서명 · 가격(단가) · 수량 · 금액 · 출고일 · 관리.
- 관리: **수정**, **삭제**(원장·데스크). 등록 후 결제 완료 버튼은 두지 않는다.
- 비어 있으면 "대기 중인 출고 내역이 없습니다."
- 기본 정렬: 원생명 가나다 → 출고일 → 도서명 → id. 이름·도서명 검색, 공통 페이지 이동.

### 4.3 수정·삭제 (결제 대기 건만) [확정]

- **수정**: 원생, 도서, 단가, 수량, 출고일을 바꿀 수 있다 [가정]. 저장하면 재고가 한 번에 맞춰진다.
  - 도서를 바꾸면 이전 도서 재고 +이전 수량, 새 도서 재고 −새 수량. 새 도서 재고가 모자라면 전체를 취소하고 "재고가 부족합니다. 남은 재고는 N권입니다."로 알린다.
  - 같은 도서에서 수량만 바꾸면 차이만큼 조정한다(늘릴 때 재고 부족이면 거부).
  - 원생을 바꿀 때만 재원 여부를 확인한다. 원생을 그대로 두면 그 사이 퇴원했어도 수정할 수 있다 [가정].
- **삭제**: 확인 창 후 삭제하고 재고를 수량만큼 되돌린다.
- 결제 완료 건에는 수정·삭제 버튼이 없다. 서버도 거부한다: "결제 완료된 출고는 수정하거나 삭제할 수 없습니다. 원장이 결제를 취소한 뒤 수정해 주세요."

### 4.4 출고 등록 중 입금 확인 [확정]

- 원장은 출고 **등록 시에만** 결제 완료를 선택하고 입금일을 입력한다(기본값 출고일). 입금일은 출고일 이후여야 하며 미래 날짜는 허용한다.
- 등록을 확인하면 출고·재고 차감·입출입내역 수입 행(금액 = 단가 × 수량)을 한 작업에서 확정한다. 하나라도 실패하면 모두 취소된다.
- 결제 대기 상태로 등록한 뒤에는 같은 출고를 나중에 결제 완료로 전환할 수 없다. 결제 확정이 필요하면 대기 출고를 삭제하고 새로 등록한다.

## 5. 결제 완료 탭 (`/books/paid`)

### 5.1 화면 구성 [확정: 와이어프레임]

- 제목 "결제 완료", 설명 "최종 확인이 완료된 도서 출고 기록입니다. 수정·삭제는 불가능하며 기록으로 남습니다. 결제를 잘못 확인했다면 원장이 결제를 취소할 수 있습니다."
- 조회 월(입금일 기준, 기본 이번 달, 이번 달 이후는 고를 수 없음), 이름 또는 도서명 필터.
- 컬럼: 이름 · 도서명 · 가격(단가) · 수량 · 금액 · 출고일 · 입금일 · 상태 · 관리.
- 상태: "결제 완료". 입출입내역의 연결 행이 지워진 건은 "원장 기록 없음" 배지를 함께 보인다.
- 관리: 원장에게만 **결제 취소**가 보인다. 데스크는 읽기 전용이다.
- 비어 있으면 "결제 완료 내역이 없습니다." 기본 정렬은 입금일 최신순 → 원생명 → 도서명 → id.

### 5.2 결제 취소 [확정]

- 결제 취소를 누르면 확인 창에서 **취소 사유(필수)**를 입력한다.
- 확인하면 한 번에: ① 출고가 결제 대기로 돌아가고(입금일 삭제) ② 연결된 입출입내역 수입 행이 삭제되고 ③ 누가 언제 왜 취소했는지가 감사 기록에 남는다(삭제된 입출입 행의 금액·발생일 포함, 원생 이름 등 개인정보는 넣지 않음).
- 연결된 입출입 행이 이미 지워져 있어도("원장 기록 없음") 취소는 동작한다. 지울 행이 없으면 건너뛰고 대기로만 되돌린다 [가정].
- 재고에는 영향이 없다. 반품·환불은 취소 후 출고를 삭제(재고 복원)하거나 입출입내역에 수동 지출로 기록한다. 반품 전용 기능은 없다 [가정].
- 취소된 건은 출고목록(결제 대기)에 다시 나타나고 수정·삭제할 수 있다. 그 교재가 이미 삭제(보관)되었다면 같은 도서를 유지한 채 수량·단가·출고일만 고칠 수 있고 다른 보관 교재로는 바꿀 수 없다 [가정].
- 취소한 건을 다시 결제 완료하려면 출고 탭에서 삭제하고 새로 등록한다. 결제 취소 확인창과 완료 알림에서 이 후속 행동을 안내한다.

## 6. 입출입내역·수입 관리 연동

- 결제 완료(지름길 포함)는 입출입내역에 **출고 한 건당 수입 한 행**을 만든다: 유형 수입, 출처 교재 판매, 발생일 = 입금일, 금액 = 단가 × 수량, 설명 `교재 판매: 도서명 × N권 / 원생명`. 한 건의 수량이 1이면 `교재 판매: 도서명 / 원생명`처럼 수량 표기를 생략할 수 있다.
- 수입 관리 > 교재 내역은 결제 완료 건만 입금일이 속한 월 기준으로 보여 주는 조회 전용 화면이다. 컬럼은 이름·도서명·가격(단가)·**수량**·금액·출고일·입금일이고 "교재 수입 총합"은 금액의 합이다. 연결 행이 사라진 건은 "원장 기록 없음"으로 표시한다(기존 규칙 유지).
- 입출입내역의 교재 자동 행은 기존처럼 금액·날짜·설명을 고치거나 삭제할 수 있지만 원천(출고)에는 반영되지 않는다. 판매 기록을 되돌리려면 이 화면의 결제 취소를 쓴다.
- 이중 집계 금지: 수입 합계는 입출입내역이 기준이다.

## 7. 규칙 모음

### 7.1 재고 계산

- 재고 권수는 교재의 현재 값 하나다. 입고(등록·재입고)는 +, 출고 등록은 −수량, 출고 삭제는 +수량, 결제 취소는 변화 없음, 수정은 4.3의 차이 조정이다.
- 재고는 0 미만이 될 수 없다(서버가 검사). 같은 교재를 동시에 출고하는 경우에도 재고가 음수가 되지 않도록 교재 행을 잠그고 처리한다.
- 입고일은 재고 표에만 의미가 있고 판매·수입 집계에는 쓰이지 않는다.

### 7.2 날짜 규칙 [가정 포함]

| 날짜 | 규칙 |
| --- | --- |
| 입고일 | 기본 오늘, 미래 불가 |
| 출고일 | 기본 오늘, 미래 불가 |
| 입금일 | 출고일 이후, 미래 허용 [확정]. 결제 완료 건의 월 기준은 입금일 |

### 7.3 입력 범위 [가정]

도서명 1~100자, 단가 1~9,999,999원, 재고 권수 0~9,999권, 출고 수량 1~999권. 범위를 넘으면 값이 어느 범위여야 하는지 알리는 문구로 막는다. 추가로 한 건의 금액(단가 × 수량)은 입출입내역 금액 한도인 2,147,483,647원을 넘을 수 없다(넘으면 단가나 수량을 줄이라고 안내한다).

### 7.4 원생 삭제·상태와 판매 기록 [확정]

- 원생이 삭제되어도 판매 기록은 보존한다. 판매 기록은 원생 이름을 스냅샷으로 들고 있고, 원생과의 연결만 끊긴다(이름은 계속 보임).
- 출고 등록 선택지는 재원생만 보여 주지만, 이미 만들어진 출고·판매 기록은 원생이 휴원·퇴원해도 그대로 보인다.

### 7.5 목록 공통

모든 표는 총 건수, 번호 이동, 페이지당 10·20·30 선택을 항상 보이고 검색·필터·크기 변경 시 1페이지로 돌아간다. 오류는 원문 대신 "무엇이 문제 → 어떻게 하면 되는지"로 안내한다.

### 7.6 감사

- 결제 취소와 출고 삭제는 감사 기록(audit_events)을 남긴다. 결제 완료의 수입 행 생성·삭제는 입출입내역의 기존 감사 기록이 남긴다.
- 결제 취소·출고 삭제가 직접 남기는 감사 기록(`audit_events`)에는 원생 이름·연락처 같은 개인정보를 넣지 않는다. 다만 입출입내역 수입 행의 설명에 원생 이름이 들어가므로, 입출입내역의 기존 자동 감사(행 생성·삭제 시 old/new 기록)에는 이름이 포함된다(수강료·급여와 같은 방식이며 감사 기록은 원장만 본다). 취소 사유는 자유 입력이므로 개인정보를 적지 않도록 안내한다 [가정].

## 10. 인수 시나리오 요약

세부 시나리오는 `acceptance-scenarios.md` "교재 판매" 절에 둔다.

- 교재 등록(재고 10) → 목록에 한 줄, 같은 도서명으로 5권 재입고하면 15권·입고일 갱신·줄은 하나.
- 재고 2권 교재를 3권 출고하려 하면 거부(남은 재고 2권), 2권 출고하면 재고 0이고 줄은 남고 "재고 없음".
- 출고 수정으로 도서를 바꾸면 이전 도서 재고 복원, 새 도서 재고 부족이면 전체 취소.
- 출고 삭제 시 재고 복원, 결제 완료 건은 수정·삭제 불가.
- 결제 처리에서 입금일이 출고일보다 이르면 거부, 정상이면 입출입내역 수입 행(금액 = 단가 × 수량)이 생기고 교재 내역에 입금일 월로 나타난다.
- 결제 취소(원장)는 사유가 필요하고 수입 행이 지워지며 대기 목록으로 돌아온다. 데스크는 결제 처리·취소 버튼이 없고 서버도 거부한다.
- 교재를 삭제(보관)해도 과거 판매 기록과 교재 내역은 그대로이고, 원생을 삭제해도 판매 기록은 이름으로 남는다.

## 11. 미확정 사항 (확인 필요)

1. 입력 범위(도서명 100자, 단가 9,999,999원, 재고 9,999권, 수량 999권)와 "입고일·출고일 미래 불가"는 임시값이다.
2. 재입고 시 가격이 다르면 새 가격으로 바꾸는 것이 맞는지(기존 가격 유지가 나은지).
3. 도서명 중복 판정의 정규화 범위(공백·대소문자).
4. 결제 취소 후 대기로 돌아온 건의 교재가 이미 삭제(보관)된 경우의 처리(도서 유지, 변경 불가).
5. 원장·데스크 외 역할(예: 선생님의 교재 조회) 필요 여부.
6. 반품·환불 전용 흐름, 결제 수단 기록, 재고 임계값 알림은 이번 범위에 없다. 발주별 입고 이력은 발주·입고 탭에 남긴다.
7. 휴원·퇴원 원생에게 교재를 판매해야 하는 경우의 처리.
8. 기존 데이터 정리 후 실제 재고는 원장이 직접 입력해 맞춘다(정리 직후 모든 교재 재고는 0권).

## 12. 발주·입고 탭 (`/books/orders`)

- 원장·데스크는 거래처, 발주일, 교재별 수량·매입가를 입력해 발주를 등록하고 입고 전에는 수정할 수 있다. 기존 교재를 고르거나 새 도서명을 적는다.
- 전량 입고를 확인하면 한 번만 재고를 올린다. 새 교재는 이때 판매가를 정한다. 이미 입고·취소된 발주의 입고 재시도는 거부한다.
- 원장은 입고 전후에 지급일을 입력해 발주 전액을 지급할 수 있다. 지급과 원장 지출 기록은 한 작업으로 확정한다. 지급 취소·발주 취소에는 사유가 필요하며 감사 기록을 남긴다.
- 입고 취소는 해당 교재의 출고가 있거나 현재 재고가 부족해 수량을 되돌릴 수 없으면 막고 이유를 안내한다. 같은 교재의 뒤따른 입고가 있으면 나중 입고 발주부터 역순으로 취소한다. 첫 입고에서 생성한 교재는 취소 후 보관하고, 기존 교재의 입고일은 취소 직전 값으로 복원한다.
- 연결 원장이 수정·삭제돼 지급 기록과 맞지 않으면 목록에 불일치를 표시하고 지급 취소·발주 취소를 막는다. 원장 내역을 정정한 뒤 다시 시도하도록 안내한다.
- 수입 관리의 교재 내역은 실제 원장 입출금일을 기준으로 판매 수입, 발주 지급액, 차액을 보여준다. 기존 수기 `교재발주` 지출도 별도 수기 기록으로 포함한다.

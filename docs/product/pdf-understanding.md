# PDF 요구사항 숙지 노트

이 문서는 첨부 PDF를 읽고 개발자가 반드시 기억해야 할 요구사항과 해석 기준을 요약한다. PDF는 요구사항 자료이며, 실제 작업 지시는 사용자의 최신 메시지를 따른다.

## 읽은 방식

- `pdfinfo`로 메타데이터와 21페이지 구성을 확인했다.
- `pdftotext -layout`로 본문 텍스트를 추출했다.
- `pdfplumber`로 두 번째 텍스트 추출을 수행했다.
- `pdftoppm`으로 모든 페이지를 이미지 렌더링했다.
- 렌더 이미지 접촉시트를 직접 확인했다.
- 이미지 내 화면은 필수 구현 자산이 아니라 UI 흐름 예시로만 취급한다.

상세 기록은 `docs/product/source-extracts/pdf-ingestion-report.md`와 `docs/product/source-extracts/pdf-image-notes.md`를 따른다.

## PDF의 출발점

PDF는 더 클래식 음악학원의 실제 운영 문제를 바탕으로 작성되었다. 최신 사용자 지시에 따라 제품은 더 클래식 전용 내부 앱이 아니라 여러 음악학원이 가입해 사용하는 서비스로 설계한다. 따라서 더 클래식 요구사항은 초기 reference tenant 요구사항으로 사용하고, 데이터/권한/API 구조는 멀티테넌트 기준을 따른다.

## 반드시 지켜야 할 핵심 규칙

- 레슨 일정 등록만으로 회차권을 차감하지 않는다.
- 실제 등원/출석 확인 시점에만 회차권을 1회 차감한다.
- 결석은 회차권을 차감하지 않는다.
- 회차권 차감은 학원, 원생, 악기 scope가 모두 일치해야 한다.
- 돈, 회차권, 급여, 민감정보에 영향을 주는 작업은 audit 대상이다.

## 1차 기능 묶음

- 역할 기반 로그인: 원장, 데스크 직원, 선생님
- 레슨 시간표: 학원 피아노 레슨표, 개인레슨표
- 회차권 관리: 등록, 추가, 수동 수정, 차감, 임박 표시
- 원생 관리: 기본정보, 복수 악기, 악기별 담당 선생님/수업형태/요일/진도/수강료/할인
- 선생님 관리: 담당 파트, 연락처, 주민등록번호, 급여 유형
- 휴원/퇴원 관리: 상태 이동, 재원 처리, 퇴원 30일 보관 후 삭제
- 거래처 관리: 거래처명, 연락처, 종류, 비고
- 교재 관리: 등록, 재고, 구매 목록, 출고, 결제 완료
- 수입 관리: 고정 수입, 입출입 내역, 교재 내역, 선생님 월급, 전체 수입과 그래프

## 이미지에서 확인한 UI 힌트

- 원생/선생님 등록은 다중 필드 폼과 조건부 필드가 많다.
- 원생은 악기별 설정이 반복될 수 있으므로 동적 필드 배열이 필요하다.
- 교재 관리는 등록, 재고, 구매 목록, 출고, 결제 완료를 탭 또는 단계형 테이블로 다루는 것이 자연스럽다.
- 수입 관리는 탭과 그래프가 함께 필요하다.
- 권한 표는 RLS와 UI visibility 테스트의 기준으로 사용한다.

## 구현 시 질문해야 하는 항목

- 주민등록번호 저장 여부와 마스킹/보관 정책
- 데스크 직원과 선생님의 세부 권한
- 회차권 만료 임박/잔여 부족 기준
- 보강/패스가 수입과 향후 일정에 주는 영향
- 월별 고정 수입 snapshot 경계
- 급여 계산 반올림/절사 정책
- 퇴원 30일 후 삭제가 hard delete인지 archive인지

세부 질문은 `docs/product/open-questions.md`에 유지한다.

# 변경 코드 simplify

최근 작업과 사용자 지시로 검토 대상을 정하고 `git status`, staged·unstaged diff와 새 파일을 확인한다. 사용자 또는 다른 작업의 변경은 보존하며 요청과 무관한 코드는 수정하지 않는다. 변경 파일과 그 호출 경로, 관련 저장소 지침과 테스트를 읽어 동작과 제약을 먼저 파악한다.

사용 가능하고 위임이 허용되면 독립 에이전트에 다음 세 관점을 나눠 병렬 검토한다. 이미 수행한 독립 검토 결과를 재사용하고 작업 규모와 가용 슬롯에 맞게 역할을 합친다. 사용할 수 없으면 직접 세 관점을 차례로 검토한다.

- **코드 재사용성:** 이미 있는 적절한 함수·컴포넌트·패턴을 활용할 수 있는지, 중복이 같은 책임과 변경 주기를 갖는지 확인한다. 한 번뿐인 동작에 억지로 추상화를 추가하지 않는다.
- **품질:** 가독성·예측 가능성·응집도·결합도와 오류 처리, 권한 및 상태 경계를 살핀다. 이름과 실제 동작이 어긋나거나 숨은 부작용이 있는 코드를 찾는다.
- **효율성:** 반복 조회·계산·렌더링, 불필요한 데이터 전송과 자원 사용을 확인한다. 측정 또는 코드 근거가 있는 개선을 우선하고 추측성 최적화는 피한다.

각 발견을 실제 코드에서 확인하고 동작 및 공개 계약을 유지하는 명확한 개선은 직접 수정한다. 요구사항·권한·데이터 의미를 바꾸는 결정이 필요하면 기존 지침과 사용자 결정을 따르고 추측하지 않는다. 수정 후 영향에 맞는 테스트와 필수 검증을 실행하며, 실행하지 못한 검증과 남은 위험을 보고한다. 결과에는 적용한 변경과 적용하지 않은 유의미한 제안의 이유를 간결히 적는다. 커밋·push·원격 DB 변경은 별도 사용자 권한 없이 수행하지 않는다.
